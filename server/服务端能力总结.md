# 服务端能力总结

> 《吞噬细胞》实时多人对战服务端 —— 当前已落地能力一览
> 阶段：P0 最小闭环（MVP）｜形态：单进程内存单体｜协议：JSON｜约 3000 行 Go

---

## 1. 总体形态

| 维度 | 当前实现 |
| --- | --- |
| 语言 / 运行时 | Go 1.24 |
| 网络 | HTTP（接口）+ WebSocket（对战，Gorilla） |
| 协议 | JSON，统一信封 |
| 进程形态 | 单体进程：API / 匹配 / 游戏 / 网关 / 结算 共享同一进程与内存 |
| 存储 | 纯内存（Redis / MySQL 暂未接入，服务边界已预留可替换） |
| 部署 | `go run ./cmd/server` 即可启动，单端口同时提供 HTTP 与 WS |

一条对局可端到端跑通：

```
游客登录 → 匹配 → 创建房间(含机器人) → WebSocket 入房 → 准备 → 倒计时
→ 20Hz 权威 Tick(移动/吃食物/吞噬) → 10Hz 快照 + 1Hz 排行榜
→ 限时结束 → 结算发奖 → 资源清理
```


## 3. 已具备的能力（按模块）

### 3.1 用户与资产
- 游客登录：按 `deviceId` 复用或新建账号，签发访问令牌（Bearer）。
- 用户信息查询、资产查询（金币 / 经验 / 等级 / 下一级所需经验）。
- 资产入账：按 `bizId` **幂等**发放金币与经验，自动按经验表重算等级。
- 等级表：L1=0 / L2=100 / L3=300 / L4=600 / L5=1000（已单测覆盖）。

### 3.2 匹配
- 开始匹配 / 取消匹配 / 查询匹配状态 / 查询模式配置。
- 后台匹配器按模式分组扫描，满足**人数门槛**或**等待超时**即成房。
- 成房后签发每位玩家的入房凭证（`enterToken`）与 `wsUrl`。
- 为便于单人验证：默认最小开局人数为 1、最长等待 3 秒。

### 3.3 房间与生命周期
- 房间状态机：`LOADING → COUNTDOWN → RUNNING → SETTLING → FINISHED`。
- 入房凭证校验（归属 + 有效期）、连接绑定、断线标记（保留球体）。
- 准备流程：全部已入房真人准备完毕即开始倒计时。
- 看门狗：长时间无人准备时强制开局；无人入房则销毁房间。
- 机器人填充：默认每房补 8 个机器人，使单人也能正常对战。

### 3.4 Game Tick 核心（权威计算）
- 固定 **20Hz** 逻辑 Tick，与广播频率解耦。
- 输入采样：按 Tick 取最新方向，带 `seq` 过期校验。
- 移动系统：方向 + 速度积分，速度随质量衰减，地图边界钳制。
- 食物系统：开局生成、周期补充至上限。
- 碰撞吞噬：玩家吃食物、大球吞小球（质量比 + 重叠深度双条件），死亡判定。
- 机器人 AI：朝最近食物移动。
- 提前结束：所有真人阵亡可不等计时直接结束。

### 3.5 状态同步
- **10Hz** 全量房间快照 `ROOM_SNAPSHOT`（玩家、球体、食物、事件）。
- **1Hz** 个性化排行榜 `RANK_UPDATE`（Top N + 自己的名次）。
- Tick 内事件累积，随下一帧快照下发（`FOOD_EATEN` / `PLAYER_EATEN` / `PLAYER_DEAD`）。
- 快照 / 排行榜均携带递增 `seq` 与 `serverTime`。

### 3.6 结算
- 限时结束触发：广播 `GAME_END` → 计算奖励 → 入账 → 推送 `SETTLEMENT_RESULT`。
- 奖励公式（详见第 6 节），金币 / 经验分别封顶。
- 幂等：按 `settlement:{roomId}:{userId}` 防重复发奖。
- 结算结果落内存，支持按房间或「最近一次」查询。
- 结束后宽限 2 秒再关闭连接并释放房间资源。

### 3.7 工程基础
- 结构化 JSON 日志贯穿全链路（`match_start` / `room_created` / `room_game_end` / `settlement_success` …）。
- HTTP 统一响应封装 `{code, message, data}`，错误码对齐设计文档。
- WebSocket 写入非阻塞（缓冲满即丢弃），慢客户端不拖垮 Tick。
- 心跳 Ping/Pong 与读超时。

## 4. HTTP 接口清单

| 方法 | 路径 | 说明 | 鉴权 |
| --- | --- | --- | --- |
| POST | `/api/auth/guest-login` | 游客登录，返回令牌与用户信息 | 否 |
| GET | `/api/users/me` | 查询当前用户信息 | 是 |
| GET | `/api/assets/me` | 查询当前用户资产 | 是 |
| POST | `/api/match/start` | 开始匹配 | 是 |
| POST | `/api/match/cancel` | 取消匹配 | 是 |
| GET | `/api/match/status` | 查询匹配状态（成功返回 roomId/wsUrl/enterToken） | 是 |
| GET | `/api/match/config` | 查询模式配置 | 否 |
| GET | `/api/settlements/{roomId}/me` | 查询本人某局结算 | 是 |
| GET | `/api/settlements/latest` | 查询本人最近一次结算 | 是 |
| GET | `/healthz` | 健康检查 | 否 |

> 鉴权方式：请求头 `Authorization: Bearer <accessToken>`。

## 5. WebSocket 协议清单

信封：`{ type, seq, serverTime, traceId, data }`，端点 `/ws`。

**客户端 → 服务端**

| 类型 | 说明 | 状态 |
| --- | --- | --- |
| `ENTER_ROOM` | 入房握手（首条消息，校验凭证） | ✅ |
| `RECONNECT` | 断线重连（可作为首条消息，校验 reconnectToken） | ✅ |
| `READY` | 加载完成 / 准备 | ✅ |
| `MOVE` | 移动方向输入 | ✅ |
| `SPLIT` | 分裂（质量阈值 40 / 分身上限 8 / 冷却 1s） | ✅ |
| `EJECT` | 吐球（质量阈值 25 / 频率 5 次每秒） | ✅ |
| `PING` | 心跳 | ✅ |

**服务端 → 客户端**

| 类型 | 说明 |
| --- | --- |
| `ENTER_ROOM_RESULT` | 入房结果（含 reconnectToken） |
| `RECONNECT_RESULT` | 重连结果 |
| `ROOM_RECOVER_SNAPSHOT` | 重连后的全量恢复快照 |
| `PLAYER_READY` | 准备进度广播 |
| `START_COUNTDOWN` | 开局倒计时 |
| `GAME_START` | 对局开始 |
| `ROOM_SNAPSHOT` | 房间状态快照（含玩家多分身、食物、吐出物、事件） |
| `RANK_UPDATE` | 局内排行榜 |
| `SKILL_FAILED` | 分裂/吐球失败原因 |
| `GAME_END` | 对局结束 |
| `SETTLEMENT_RESULT` | 结算结果 |
| `PONG` / `ERROR` | 心跳响应 / 错误 |

> HTTP 已开启 CORS（允许跨域 + 处理 OPTIONS），浏览器客户端可跨端口直连。

## 6. 核心玩法参数与公式

**默认配置（`config.Default()`）**

| 参数 | 值 | 参数 | 值 |
| --- | --- | --- | --- |
| 逻辑 Tick | 20/s | 地图 | 4000 × 4000 |
| 快照广播 | 10/s | 初始 / 上限食物 | 400 / 500 |
| 排行榜 | 1/s | 玩家初始质量 | 20 |
| 倒计时 | 3s | 基础速度 | 280 |
| 对局时长 | 60s | 机器人数量 | 8 |

**关键公式**

```text
半径      radius = sqrt(mass) * 2.5
速度      speed  = baseSpeed / sqrt(mass / 初始质量)        # 越大越慢，封顶 baseSpeed
吃食物    distance <= 球半径 + 食物半径
吞噬玩家  攻击方质量 >= 目标质量 * 1.2
          且 distance <= 攻击方半径 - 目标半径 * 0.4
吞噬增重  攻击方 += 目标质量 * 0.8
```

**分裂 / 吐球常量**

```text
分裂  最小质量 40，分身上限 8，冷却 1s，新球=源球*0.5，冲量 600（500ms 线性衰减），10s 后可合体
合体  同主、到期、重叠（距离<=较大球半径）的两球合并
吐球  最小质量 25，每次扣 5，最小间隔 150ms，每秒上限 5，初速 400（飞行 300ms 后静止），原主 300ms 内不可吃回
```

**断线重连常量**

```text
重连窗口 30s（断线后保留玩家，STOP 策略：停止移动仍可被吃，超窗判负）
reconnectToken 入房时下发，TTL 600s
```

**结算奖励**

```text
金币 = 50 + 排名档位 + 吞噬玩家数*10 + floor(吃食物数*0.1)        # 封顶 1000
经验 = 30 + 排名档位 + floor(存活秒数*0.2) + 吞噬玩家数*5         # 封顶 800
排名档位（金币/经验）：1名 300/200，2名 200/150，3名 150/120，
                       4-10名 80/60，11-30名 30/30，31名+ 0/0
```

## 8. 运行方式

```bash
cd server
go run ./cmd/server                     # 默认监听 :8080，WS 路径 /ws

# 自定义端口 / 对外地址：
HTTP_ADDR=:18080 WS_HOST=localhost:18080 go run ./cmd/server
```

> `WS_HOST` 用于设置匹配接口返回给客户端的 `wsUrl` 指向的地址。

## 9. 当前边界（尚未实现）

已落地：P0 最小闭环 + P1 的**分裂/吐球**（含多分身、合体、吐出物）与**断线重连**。

以下属于 P2，尚未落地：

- 刺球（Virus）机制
- 战绩记录、全服排行榜（`/api/records`、`/api/ranks`）
- AOI 视野裁剪、增量快照、Protobuf 协议
- Redis / MySQL 持久化（当前全内存，进程退出即丢失）
- 多 Game Server 调度与房间分片

> 协议与 Tick 系统已为上述能力预留扩展位；存储可在 `user` / `settlement`
> 服务边界后接入真实数据库而不改动上层逻辑。

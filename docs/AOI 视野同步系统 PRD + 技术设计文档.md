# 第一部分：AOI 视野同步系统 PRD

## 2. 模块背景

《吞噬细胞》目标支持单局 100 人实时对战。随着玩家数量、食物数量、刺球数量、吐出物数量增加，如果服务端将全地图所有对象都同步给每一个客户端，会带来较大的网络和客户端渲染压力。

AOI 是 Area Of Interest 的缩写，可以理解为“玩家感兴趣区域”或“玩家视野范围”。在游戏中，每个玩家只需要接收自己附近、视野内、可能影响当前操作的对象，而不需要接收地图另一端的玩家和食物。

AOI 视野同步系统需要解决以下问题：

1. 每个玩家应该看到哪些对象。
2. 服务端如何快速查询玩家附近对象。
3. 对象进入视野时如何通知客户端。
4. 对象离开视野时如何通知客户端。
5. 玩家移动时视野范围如何变化。
6. AOI 如何减少状态同步包体。
7. AOI 如何降低客户端渲染对象数量。
8. AOI 如何与全量快照、增量快照配合。

------

## 3. 模块目标

### 3.1 产品目标

| 目标             | 说明                                   |
| ---------------- | -------------------------------------- |
| 减少无关对象干扰 | 玩家只看到自己视野内相关对象           |
| 降低画面压力     | 客户端只渲染附近对象，减少对象数量     |
| 保持对战体验     | 视野内对象变化需要及时、平滑           |
| 支持百人同局     | 单局 100 人时仍能控制同步和渲染压力    |
| 保证关键事件可见 | 视野内吞噬、分裂、吐球等事件应正确展示 |
| 减少带宽消耗     | 不向每个玩家广播全地图对象             |
| 支持视野变化     | 玩家变大后视野可以适当扩大             |

### 3.2 技术目标

| 目标              | 说明                                         |
| ----------------- | -------------------------------------------- |
| 服务端视野过滤    | Game Server 按玩家视野生成个性化快照         |
| 空间索引          | 使用网格等方式快速查询附近对象               |
| 进入/离开视野事件 | 支持对象出现和消失的生命周期管理             |
| 支持增量同步      | AOI 与增量快照配合，减少数据量               |
| 支持全量恢复      | 重连或状态异常时可下发当前视野完整快照       |
| 性能可观测        | 监控每个玩家可见对象数量、快照大小、过滤耗时 |
| 可配置            | 视野半径、网格大小、同步频率可配置           |

------

## 4. AOI 系统定位

AOI 位于 RoomState 和 SnapshotSystem 之间。

```text
RoomState 全量房间状态
  ↓
AOI Filter
  ↓
PlayerVisibleState 玩家可见状态
  ↓
SnapshotSystem
  ↓
WebSocket
  ↓
Cocos Client
```

没有 AOI 时：

```text
每个玩家收到全房间状态
```

加入 AOI 后：

```text
每个玩家只收到自己视野范围内的状态
```

------

## 5. 核心设计原则

## 5.1 服务端决定可见范围

客户端不能自己声明“我看到了哪些对象”。
服务端根据玩家位置、球体半径、视野范围、地图对象位置计算可见对象集合。

------

## 5.2 AOI 不改变游戏规则

AOI 只影响“同步给客户端的对象范围”，不影响服务端权威计算。

例如：

1. 服务端仍然维护全房间状态。
2. 服务端仍然计算全房间碰撞和吞噬。
3. AOI 只决定给某个玩家发送哪些对象。
4. 即使对象不在玩家视野内，它仍然存在于服务端房间状态中。

------

## 5.3 先网格，后优化

MVP 优化阶段建议采用网格 AOI。

```text
地图切成网格
对象归属网格
玩家查询周围网格
得到可见对象
```

后续如果对象数量进一步增加，再考虑更复杂的空间索引。

------

## 5.4 进入视野和离开视野要明确

客户端需要知道：

1. 哪些对象是新出现的。
2. 哪些对象仍然存在。
3. 哪些对象已经离开视野。
4. 哪些对象被吞噬或删除。

否则客户端会出现残影、对象不消失、对象突然闪现等问题。

------

## 5.5 AOI 与客户端表现解耦

服务端只负责告诉客户端对象是否可见。
客户端负责：

1. 创建对象节点。
2. 隐藏对象节点。
3. 播放出现动画。
4. 播放消失动画。
5. 回收对象池。

------

# 6. 用户场景

## 6.1 玩家在地图中移动

### 场景描述

玩家在地图中移动时，视野范围也随之移动。服务端需要不断计算玩家附近可见对象，并同步给客户端。

### 同步表现

```text
玩家移动
  ↓
视野范围变化
  ↓
部分对象进入视野
  ↓
部分对象离开视野
  ↓
客户端创建 / 更新 / 移除对象
```

------

## 6.2 远处玩家不再同步

### 场景描述

地图另一端的玩家与当前玩家没有交互关系，不需要同步给当前客户端。

### 产品表现

1. 当前玩家不会看到地图另一端的玩家。
2. 排行榜仍可以显示全局排名。
3. 小地图后续可用抽象点位展示，和 AOI 详细对象同步分离。

------

## 6.3 对象进入视野

### 场景描述

当前玩家移动到某个区域后，一个敌方玩家或食物进入视野。

### 产品表现

1. 客户端创建该对象。
2. 对象出现在地图上。
3. 可选择淡入或直接显示。
4. 后续快照继续更新该对象位置。

------

## 6.4 对象离开视野

### 场景描述

当前玩家远离某个对象，该对象离开视野。

### 产品表现

1. 客户端收到删除或离开视野消息。
2. 对象从画面中移除。
3. 可选择直接隐藏或淡出。
4. 对象节点回收到对象池。

------

## 6.5 玩家变大后视野扩大

### 场景描述

玩家质量变大后，视野范围可以适当扩大，让玩家看到更大的地图范围。

### 产品表现

1. 画面镜头可能缩放。
2. 可见区域变大。
3. 服务端同步范围随之增大。
4. 客户端可能看到更多对象。

------

# 7. 功能范围

## 7.1 MVP 阶段

MVP 阶段可以不做 AOI，只做全房间广播。

但是数据结构应预留 AOI 接入点：

1. 快照生成前预留 AOIFilter。
2. 对象拥有 position 字段。
3. 对象拥有 objectId 和 objectType。
4. 客户端支持对象新增、更新、删除。
5. 快照支持 deletes 字段，方便后续对象离开视野。

------

## 7.2 AOI 第一阶段功能范围

第一阶段 AOI 需要实现：

1. 地图网格划分。
2. 玩家、食物、刺球、吐出物归属网格。
3. 玩家可见网格计算。
4. 可见对象查询。
5. 按玩家生成可见快照。
6. 对象进入视野同步。
7. 对象离开视野同步。
8. AOI 全量恢复快照。
9. AOI 指标统计。

------

## 7.3 AOI 完整版本功能范围

完整版本可扩展：

1. 增量 AOI 快照。
2. 动态视野半径。
3. 多球体玩家视野合并。
4. 大对象跨网格处理。
5. 小地图低频摘要同步。
6. 高价值对象优先同步。
7. 分批同步食物对象。
8. AOI 快照压缩。
9. Protobuf 二进制协议。
10. 可见对象数量限制。
11. 弱网下降级同步。

------

## 7.4 暂不包含范围

当前 AOI 文档不详细展开：

1. 碰撞检测空间分区详细算法。
2. 客户端预测回滚。
3. 小地图全局信息同步。
4. 观战模式视野。
5. 队友共享视野。
6. 战争迷雾机制。
7. 多 Game Server 跨服 AOI。

# 8. AOI 对象范围

## 8.1 需要纳入 AOI 的对象

| 对象         | 是否纳入 AOI | 说明                  |
| ------------ | ------------ | --------------------- |
| 玩家球体     | 是           | 主要同步对象          |
| 食物         | 是           | 数量多，必须过滤      |
| 刺球         | 是           | 地图重要对象          |
| 吐出物       | 是           | 高频变化对象          |
| 技能特效     | 可选         | 可由事件驱动          |
| 局内排行榜   | 否           | 低频全局信息          |
| 游戏倒计时   | 否           | 全局信息              |
| 当前玩家自身 | 必须同步     | 不受普通 AOI 过滤影响 |
| 结算结果     | 否           | 全局结果消息          |

------

## 8.2 不受 AOI 影响的消息

以下消息不应被 AOI 过滤：

1. 游戏开始。
2. 游戏结束。
3. 当前玩家自身状态。
4. 当前玩家结算结果。
5. 系统错误消息。
6. 心跳消息。
7. 局内排行榜消息。
8. 断线重连结果。

# 10. 空间网格设计

## 10.1 网格划分

将地图按固定大小切分为网格。

示例：

```text
地图大小：10000 x 10000
网格大小：500 x 500
网格数量：20 x 20 = 400 个网格
```

每个对象根据坐标归属到某个网格。

------

## 10.2 网格 Key 计算

```text
gridX = floor(x / gridSize)
gridY = floor(y / gridSize)
gridKey = gridX + ":" + gridY
```

例如：

```text
x = 1200
y = 800
gridSize = 500

gridX = 2
gridY = 1
gridKey = "2:1"
```

------

## 10.3 网格存储内容

每个网格维护对象集合：

```text
GridCell
├── players
├── foods
├── viruses
└── ejectedMass
```

------

## 10.4 对象网格更新

对象移动时需要检查是否跨网格。

```text
对象旧 gridKey
  ↓
根据新坐标计算新 gridKey
  ↓
如果 gridKey 未变化，不处理网格归属
  ↓
如果 gridKey 变化，从旧网格移除，加入新网格
```

玩家球体、吐出物等移动对象需要频繁更新网格。
食物和刺球通常静态，只有被生成或删除时更新网格。

# 11. 视野范围设计

## 11.1 基础视野范围

每个玩家有一个视野半径。

```text
viewRadius = baseViewRadius + radius * viewFactor
```

示例：

```text
baseViewRadius = 1200
viewFactor = 5
```

玩家越大，视野可以越大。

------

## 11.2 视野中心

如果玩家只有一个球体：

```text
视野中心 = 玩家球体中心
```

如果玩家拥有多个分身：

```text
视野中心 = 多个球体中心点的平均值
```

或：

```text
视野范围 = 多个球体视野范围的并集
```

MVP 阶段建议：

```text
多球体中心点平均值 + 最大球体半径计算视野
```

完整版本可使用多个球体视野并集。

------

## 11.3 可见网格计算

根据玩家视野范围计算覆盖的网格区间。

```text
minGridX = floor((centerX - viewRadius) / gridSize)
maxGridX = floor((centerX + viewRadius) / gridSize)

minGridY = floor((centerY - viewRadius) / gridSize)
maxGridY = floor((centerY + viewRadius) / gridSize)
```

然后遍历这些网格，收集候选对象。

------

## 11.4 精确距离过滤

网格查询得到的是候选对象，需要进一步做距离判断。

```text
distance(objectPosition, viewCenter) <= viewRadius + objectRadius
```

这样可以避免同步视野范围外但处于相邻网格中的对象。

# 12. VisibleSet 设计

## 12.1 VisibleSet 定义

VisibleSet 表示某个玩家当前可见的对象 ID 集合。

```text
VisibleSet
├── visiblePlayers
├── visibleFoods
├── visibleViruses
└── visibleEjectedMass
```

------

## 12.2 上一帧与当前帧对比

服务端为每个玩家维护：

```text
lastVisibleSet
currentVisibleSet
```

对比后得到：

```text
entered = currentVisibleSet - lastVisibleSet
left = lastVisibleSet - currentVisibleSet
stayed = currentVisibleSet ∩ lastVisibleSet
```

含义：

| 集合    | 说明               |
| ------- | ------------------ |
| entered | 新进入视野的对象   |
| left    | 离开视野的对象     |
| stayed  | 持续在视野中的对象 |

------

## 12.3 同步策略

| 对象状态 | 同步方式                 |
| -------- | ------------------------ |
| entered  | 下发完整对象数据         |
| stayed   | 下发位置、状态等变化字段 |
| left     | 下发删除 / 离开视野      |
| deleted  | 下发删除事件             |
| self     | 始终同步完整或核心状态   |

------

1. 首次进入对局。

```json
    "visibleObjects": {
      "players": [],
      "foods": [],
      "viruses": [],
      "ejectedMass": []
    },
    "events": []
  }
}
```

## 13.3 对象删除与离开视野的区别

| 类型    | 说明                                 | 客户端表现                |
| ------- | ------------------------------------ | ------------------------- |
| left    | 对象离开当前玩家视野，但仍存在于房间 | 从当前客户端画面移除      |
| deleted | 对象被吞噬、死亡或销毁               | 播放删除/吞噬效果，并移除 |
| hidden  | 服务端临时不再同步，后续可恢复       | 客户端隐藏或回收          |

建议消息中明确区分：

```text
leftObjects
deletedObjects
```

# 14. 服务端 AOI 流程

## 14.1 每次快照生成流程

```text
1. Tick 更新 RoomState
2. 更新空间网格中对象位置
3. 遍历房间内玩家
4. 计算玩家视野中心和视野半径
5. 根据视野范围查询相关网格
6. 对候选对象做精确距离过滤
7. 得到 currentVisibleSet
8. 与 lastVisibleSet 对比
9. 生成 entered / updated / left / deleted
10. 生成玩家个性化 AOI 快照
11. 通过 WebSocket 发送给该玩家
12. 更新 lastVisibleSet
```

------

## 14.2 网格更新流程

```text
1. 对象位置发生变化
2. 计算对象新的 gridKey
3. 判断新旧 gridKey 是否一致
4. 一致则不更新空间索引
5. 不一致则从旧 GridCell 移除
6. 加入新 GridCell
7. 更新对象当前 gridKey
```

------

## 14.3 玩家多球体 AOI 流程

MVP 建议：

```text
1. 计算玩家所有球体中心平均值
2. 找出最大球体半径
3. 根据最大半径计算视野半径
4. 以平均中心为视野中心
```

完整版本：

```text
1. 每个球体独立计算视野范围
2. 查询每个球体周围对象
3. 多个结果集合并
4. 去重后生成可见对象集合
```

------

# 15. 客户端 AOI 流程

## 15.1 客户端接收 AOI 全量快照

```text
1. 收到 AOI_FULL_SNAPSHOT
2. 清空当前可见对象集合
3. 创建 self 对象
4. 创建 visibleObjects 中的对象
5. 更新 SnapshotBuffer
6. 开始正常插值渲染
```

------

## 15.2 客户端接收 AOI 增量快照

```text
1. 收到 AOI_DELTA
2. 校验 baseSeq 是否连续
3. 更新 self 状态
4. 处理 entered 对象，创建实体
5. 处理 updated 对象，更新目标状态
6. 处理 left 对象，移除或隐藏实体
7. 处理 deleted 对象，播放事件后移除
8. 写入 SnapshotBuffer
```

------

## 15.3 baseSeq 不连续处理

如果客户端发现：

```text
AOI_DELTA.baseSeq != lastSeq
```

则说明客户端状态可能不完整。

处理：

```text
1. 暂停处理该增量快照
2. 向服务端请求 FULL_SYNC
3. 服务端返回 AOI_FULL_SNAPSHOT
4. 客户端基于全量快照恢复状态
```

------

## 15.4 客户端对象生命周期

| 服务端状态 | 客户端处理                       |
| ---------- | -------------------------------- |
| entered    | 从对象池取节点并显示             |
| updated    | 更新目标状态，插值移动           |
| left       | 播放淡出或直接隐藏，回收到对象池 |
| deleted    | 播放吞噬/死亡特效后回收          |
| self       | 始终保持显示并优先更新           |

------

# 16. AOI 与排行榜、小地图的关系

## 16.1 局内排行榜

排行榜不受 AOI 过滤。

原因：

1. 排行榜是全局信息。
2. 玩家需要知道全局排名。
3. 排行榜不依赖对象位置完整同步。
4. 排行榜低频推送，数据量较小。

------

## 16.2 小地图

小地图可以和 AOI 详细对象同步分开。

建议：

1. 对战主画面使用 AOI 详细对象同步。
2. 小地图使用低频摘要同步。
3. 小地图只显示粗略位置，不显示完整对象状态。
4. 小地图可以只显示 Top 玩家、自己、危险区域等信息。

------

# 17. AOI 与碰撞系统的关系

AOI 和碰撞系统都可能使用空间网格，但职责不同。

| 模块     | 目的                       |
| -------- | -------------------------- |
| AOI      | 决定同步给客户端哪些对象   |
| 碰撞系统 | 决定哪些对象发生碰撞或吞噬 |

两者可以共享空间索引，也可以分别维护。

MVP 后续优化建议：

```text
先让 AOI 和碰撞系统共享同一套 SpatialGrid
```

但要注意：

1. AOI 查询范围通常与视野相关。
2. 碰撞查询范围通常与对象半径相关。
3. 两者查询半径和过滤条件不同。

# 18. 性能设计

## 18.1 AOI 降低的压力

AOI 可以降低：

1. 服务端单个快照包体。
2. WebSocket 广播总字节数。
3. 客户端解析对象数量。
4. 客户端渲染对象数量。
5. 客户端对象创建和销毁压力。
6. 食物等大量对象同步压力。

## 18.4 可见对象上限

为了防止局部区域对象过多，服务端可以设置可见对象上限。

例如：

```text
最多同步最近 800 个食物
最多同步最近 60 个玩家球体
最多同步最近 100 个吐出物
```

排序策略：

1. 距离玩家越近优先级越高。
2. 玩家对象优先级高于食物。
3. 危险对象优先级高于普通对象。
4. 当前玩家自身对象永远同步。

# 19. 弱网与异常处理

## 19.1 增量丢失

如果客户端丢失增量快照：

```text
baseSeq 不连续
  ↓
客户端请求全量恢复
```

------

## 19.2 对象残留

如果客户端本地存在服务端已经不再同步的对象：

处理方式：

1. 通过 leftObjects 移除。
2. 通过周期全量快照校正。
3. 客户端增加对象过期清理。
4. 对象长时间未更新则隐藏。

------

## 19.3 视野边界抖动

对象在视野边界附近可能频繁进入/离开。

优化方式：

1. 增加 AOI 缓冲区。
2. 进入半径与离开半径分离。
3. 离开视野延迟移除。
4. 客户端淡入淡出。

示例：

```text
进入半径 = viewRadius
离开半径 = viewRadius + 200
```

这样可以减少边界抖动。

# 23. 安全与校验

## 23.1 服务端校验

服务端需要校验：

1. 玩家是否在房间内。
2. 房间是否处于 RUNNING。
3. 玩家是否有有效球体。
4. 视野半径是否在合理范围内。
5. 网格范围是否越界。
6. 可见对象数量是否超过上限。
7. 快照大小是否超过限制。
8. 断线玩家是否需要跳过同步。

------

## 23.2 客户端校验

客户端需要校验：

1. roomId 是否匹配。
2. userId 是否匹配当前玩家。
3. seq 是否连续。
4. baseSeq 是否连续。
5. entered / updated / left 字段是否完整。
6. 对象类型是否合法。
7. 对象坐标是否异常。
8. 快照异常时请求全量恢复。

# 26. 总结

AOI 视野同步系统是《吞噬细胞》支撑单局 100 人实时对战的重要优化模块。它的核心目标是：

```text
不是把全地图对象同步给每个玩家
而是只同步玩家视野范围内的对象
```

核心链路如下：

```text
RoomState
  ↓
空间网格
  ↓
计算玩家视野
  ↓
查询可见对象
  ↓
生成 AOI 快照
  ↓
客户端创建 / 更新 / 移除对象
```

MVP 阶段可以先不实现 AOI，但应在状态同步结构中预留 AOI 接入点。进入性能优化阶段后，优先实现网格 AOI，再结合增量同步、对象池、Protobuf 和快照压缩，逐步支撑单局 100 人对战体验。

当前阶段关键设计原则：

1. AOI 只影响同步范围，不影响服务端权威计算。
2. 当前玩家自身状态必须始终同步。
3. 局内排行榜、游戏倒计时、结算结果不受 AOI 过滤。
4. 服务端负责计算可见对象集合。
5. 客户端负责对象创建、更新、隐藏和回收。
6. AOI 需要和增量同步结合，才能充分降低带宽压力。
7. 周期性全量快照用于校正客户端状态。

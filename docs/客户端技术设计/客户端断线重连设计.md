# 2. 设计目标

客户端断线重连系统用于处理玩家在对战过程中出现的连接异常。

需要覆盖以下情况：

```text
WebSocket 异常断开
心跳超时
移动端浏览器切后台
H5 页面失焦
网络短暂抖动
玩家锁屏后回来
Game Server 主动断开连接
游戏已经结束但客户端没收到结算
```

设计目标：

1. 断线后不要立即丢失对局。
2. 短时间断线可以自动恢复。
3. 重连期间暂停输入，避免发送无效操作。
4. 重连成功后通过服务端恢复快照重建画面。
5. 重连失败后返回大厅或查询结算。
6. 游戏已经结束时优先找回结算结果。
7. 客户端不自己伪造对局状态。
8. 给玩家明确的 UI 反馈。

------

# 3. 设计原则

## 3.1 服务端权威恢复

客户端重连成功后，不能使用断线前的本地状态继续游戏。

必须以服务端下发的恢复快照为准：

```text
断线
  ↓
重连成功
  ↓
发送 RECONNECT
  ↓
服务端校验
  ↓
下发 ROOM_RECOVER_SNAPSHOT
  ↓
客户端清空旧状态
  ↓
重建对战画面
```

------

## 3.2 重连期间禁止输入

重连期间客户端必须停止发送：

```text
MOVE
SPLIT
EJECT
PING，旧连接上的心跳也停止
```

UI 表现：

```text
摇杆禁用
技能按钮置灰
显示“正在重连...”
```

------

## 3.3 短断线尝试恢复，长断线走失败兜底

推荐重连窗口：

```text
30 秒
```

如果服务端认为玩家还在重连窗口内，则允许恢复。

如果超过窗口：

```text
返回大厅
或
查询结算结果
```

------

## 3.4 已结束对局优先查询结算

如果断线时服务端房间已经结束，客户端不应该继续尝试恢复对战，而应该查询结算。

```text
重连失败原因 = ROOM_FINISHED
  ↓
GET /api/settlements/{roomId}/me
  ↓
有结果 → SettlementScene
  ↓
无结果 → LobbyScene，提示稍后查看战绩
```

# 5. 断线来源分类

## 5.1 WebSocket close

常见原因：

1. 服务端主动关闭。
2. 网络断开。
3. 浏览器网络切换。
4. 移动端锁屏。
5. 页面切后台。
6. Token 或房间状态异常。
7. 服务端异常。

------

## 5.2 心跳超时

心跳配置：

| 配置                | 建议值 |
| ------------------- | ------ |
| heartbeatIntervalMs | 5000   |
| heartbeatTimeoutMs  | 15000  |
| maxMissedHeartbeat  | 3      |

判定逻辑：

```text
连续 3 次未收到 PONG
  ↓
认为连接异常
  ↓
主动关闭旧连接
  ↓
进入重连流程
```

------

## 5.3 H5 页面失焦

H5 页面可能触发：

```text
visibilitychange
blur
pagehide
freeze
```

处理策略：

| 事件                     | 处理                     |
| ------------------------ | ------------------------ |
| visibilitychange hidden  | 暂停输入，记录状态       |
| visibilitychange visible | 检查 WS 状态，必要时重连 |
| blur                     | 摇杆归零，停止 MOVE      |
| pagehide                 | 停止输入，等待恢复       |
| beforeunload             | 正常关闭连接，后续可选   |

------

## 5.4 网络切换

移动端从 Wi-Fi 切到 4G，或反过来，可能导致 WebSocket 断开。

处理：

```text
监听 WebSocket close
  ↓
进入重连流程
```

可辅助监听：

```text
window.online
window.offline
```

------

# 6. 客户端重连状态机

## 6.1 网络状态

| 状态             | 说明           |
| ---------------- | -------------- |
| CONNECTED        | WebSocket 正常 |
| DISCONNECTED     | 已断开         |
| RECONNECTING     | 正在重连       |
| RECONNECTED      | 重连成功       |
| RECOVERING       | 等待恢复快照   |
| RECOVERED        | 恢复完成       |
| RECONNECT_FAILED | 重连失败       |
| CLOSED           | 主动关闭       |

------

## 6.2 对战状态联动

| Battle 状态   | 重连行为                       |
| ------------- | ------------------------------ |
| WAITING_START | 可以重连                       |
| PLAYING       | 可以重连                       |
| DEAD          | 可以重连，但可能只恢复死亡状态 |
| ENDING        | 不恢复对战，优先查结算         |
| SETTLED       | 不重连                         |
| CLOSED        | 不重连                         |

------

## 6.3 状态流转

```text
PLAYING
  ↓ WebSocket 断开 / 心跳超时
DISCONNECTED
  ↓
RECONNECTING
  ↓ WebSocket 重新连接成功
RECOVERING
  ↓ RECONNECT_RESULT success + ROOM_RECOVER_SNAPSHOT
RECOVERED
  ↓
PLAYING
```

失败：

```text
RECONNECTING
  ↓ 尝试次数耗尽 / 服务端拒绝
RECONNECT_FAILED
  ↓
SettlementScene / LobbyScene
```

------

# 7. 重连前置条件

客户端只有满足以下条件才尝试重连：

1. 当前在 GameScene。
2. 当前有 roomId。
3. 当前有 wsUrl 或可查询房间路由。
4. 当前有 reconnectToken。
5. 当前对局未明确结算完成。
6. 断开不是客户端主动退出。
7. 断开不是 Token 失效导致。

------

## 7.1 不应该重连的情况

| 情况                     | 处理             |
| ------------------------ | ---------------- |
| 玩家主动返回大厅         | 不重连           |
| 玩家退出对局             | 不重连           |
| Token 失效               | 跳 LoginScene    |
| 已收到 SETTLEMENT_RESULT | 不重连           |
| 房间已结束               | 查询结算         |
| 没有 reconnectToken      | 返回大厅         |
| 服务端明确禁止重连       | 返回大厅或查结算 |

------

# 8. 重连核心流程

## 8.1 简化流程

```text
WebSocket 断开
  ↓
停止输入
  ↓
显示 ReconnectPanel
  ↓
停止旧 Heartbeat
  ↓
尝试重新连接 wsUrl
  ↓
连接成功
  ↓
发送 RECONNECT
  ↓
收到 RECONNECT_RESULT
  ↓
收到 ROOM_RECOVER_SNAPSHOT
  ↓
清空本地状态并重建
  ↓
恢复输入
  ↓
关闭 ReconnectPanel
```

------

## 8.2 完整流程

```text
onWsClose
  ↓
判断是否主动关闭
  ├── 是 → 不重连
  └── 否
      ↓
判断是否允许重连
      ├── 否 → 兜底处理
      └── 是
          ↓
InputManager.disable()
          ↓
HeartbeatClient.stop()
          ↓
ReconnectPanel.show()
          ↓
ReconnectClient.start()
          ↓
connect wsUrl
          ↓
onOpen
          ↓
send RECONNECT
          ↓
等待 RECONNECT_RESULT
          ↓
success?
          ├── 否 → handleReconnectFailed
          └── 是
              ↓
等待 ROOM_RECOVER_SNAPSHOT
              ↓
BattleState.clear()
              ↓
EntityManager.clearAll()
              ↓
SnapshotReceiver.handleRecoverSnapshot()
              ↓
InputManager.enable()
              ↓
HeartbeatClient.start()
              ↓
ReconnectPanel.hide()
```

# 9. 重连退避策略

## 9.1 尝试次数

MVP 推荐：

```text
maxReconnectAttempts = 3
```

P1 推荐：

```text
maxReconnectAttempts = 5
```

------

## 9.2 退避间隔

MVP 推荐：

```json
[0, 1000, 2000, 3000]
```

含义：

| 第几次  | 等待时间 |
| ------- | -------- |
| 第 1 次 | 0ms      |
| 第 2 次 | 1000ms   |
| 第 3 次 | 2000ms   |
| 第 4 次 | 3000ms   |

------

## 9.3 重连窗口

客户端本地最多尝试：

```text
30 秒
```

超过 30 秒后停止尝试。

服务端也需要有自己的重连窗口，客户端不能只依赖本地时间判断。

------

# 10. RECONNECT 协议

## 10.1 客户端发送

```json
{
  "type": "RECONNECT",
  "seq": 9101,
  "traceId": "trace_xxx",
  "clientTime": 1710000000000,
  "roomId": "r_90001",
  "data": {
    "reconnectToken": "reconnect_token_xxx",
    "lastClientSnapshotSeq": 3001,
    "lastClientTickSeq": 520,
    "clientVersion": "1.0.0",
    "protocolVersion": "json-v1"
  }
}
```

------

## 10.2 字段说明

| 字段                  | 说明                           |
| --------------------- | ------------------------------ |
| roomId                | 当前房间 ID                    |
| reconnectToken        | 入房成功后服务端下发的重连凭证 |
| lastClientSnapshotSeq | 客户端最后处理的快照 seq       |
| lastClientTickSeq     | 客户端最后处理的 tickSeq       |
| clientVersion         | 客户端版本                     |
| protocolVersion       | 协议版本                       |

------

# 11. RECONNECT_RESULT 协议

## 11.1 成功

```json
{
  "type": "RECONNECT_RESULT",
  "seq": 9101,
  "serverTime": 1710000000050,
  "roomId": "r_90001",
  "data": {
    "success": true,
    "status": "RECONNECTED",
    "message": "重连成功"
  }
}
```

------

## 11.2 失败

```json
{
  "type": "RECONNECT_RESULT",
  "seq": 9101,
  "serverTime": 1710000000050,
  "roomId": "r_90001",
  "data": {
    "success": false,
    "reason": "RECONNECT_TIMEOUT",
    "message": "重连超时，已退出对局"
  }
}
```

------

## 11.3 失败原因

| reason             | 说明         | 客户端处理           |
| ------------------ | ------------ | -------------------- |
| TOKEN_INVALID      | 重连凭证无效 | 返回大厅             |
| TOKEN_EXPIRED      | 重连凭证过期 | 查询结算或返回大厅   |
| ROOM_NOT_FOUND     | 房间不存在   | 查询结算             |
| ROOM_FINISHED      | 房间已结束   | 查询结算             |
| RECONNECT_TIMEOUT  | 超出重连窗口 | 查询结算或返回大厅   |
| PLAYER_NOT_IN_ROOM | 玩家不在房间 | 返回大厅             |
| SERVER_ERROR       | 服务端异常   | 可再试，最终返回大厅 |

------

# 12. ROOM_RECOVER_SNAPSHOT 协议

## 12.1 恢复快照

```json
{
  "type": "ROOM_RECOVER_SNAPSHOT",
  "seq": 9102,
  "serverTime": 1710000000060,
  "roomId": "r_90001",
  "data": {
    "tickSeq": 1520,
    "snapshotType": "FULL_RECOVER",
    "remainingSeconds": 120,
    "selfUserId": "10001",
    "roomStatus": "RUNNING",
    "players": [],
    "foods": [],
    "ejectedMass": [],
    "viruses": [],
    "rank": {
      "topN": [],
      "selfRank": {
        "rank": 6,
        "score": 2400,
        "totalPlayers": 100
      }
    },
    "events": []
  }
}
```

------

## 12.2 客户端处理

收到恢复快照后：

```text
停止旧渲染更新
  ↓
清空 BattleState
  ↓
清空 SnapshotBuffer
  ↓
EntityManager.clearAll()
  ↓
ObjectPool 回收实体
  ↓
按恢复快照重建 BattleState
  ↓
重建玩家、食物、吐出物等实体
  ↓
恢复 RankPanel
  ↓
恢复 HUD
  ↓
恢复输入
  ↓
恢复心跳
```

# 13. UI 设计

## 13.1 ReconnectPanel 状态

| 状态                 | 文案                             | 按钮     |
| -------------------- | -------------------------------- | -------- |
| RECONNECTING         | 网络不稳定，正在重连...          | 无       |
| RETRYING             | 正在重连，第 N 次...             | 无       |
| RECOVERING           | 正在恢复对局...                  | 无       |
| FAILED               | 重连失败                         | 返回大厅 |
| SETTLEMENT_QUERYING  | 对局已结束，正在查询结算...      | 无       |
| SETTLEMENT_NOT_FOUND | 暂未查询到结算，可稍后在战绩查看 | 返回大厅 |

------

## 13.2 重连期间 UI 表现

重连期间：

1. 半透明遮罩覆盖对战画面。
2. 摇杆不可用。
3. 技能按钮置灰。
4. HUD 可以保留，但不再刷新。
5. 显示重连中动画。
6. 不允许点击返回大厅以外的复杂操作，MVP 可不提供返回大厅按钮。

------

## 13.3 重连失败 UI

文案：

```text
重连失败，请返回大厅
```

如果可能已经结算：

```text
对局可能已经结束，正在为你查询结算结果
```

如果结算还没生成：

```text
暂未查询到结算结果，可稍后在战绩中查看
```

# 14. 输入系统处理

## 14.1 断线时

进入断线状态后：

```text
InputManager.disable()
MoveInputSender.stop()
SkillButtonController.disable()
JoystickController.reset()
```

并立即停止发送 MOVE。

------

## 14.2 重连成功后

收到恢复快照后：

```text
InputManager.setState(PLAYING)
MoveInputSender.start()
SkillButtonController.enable()
JoystickController.enable()
```

注意：必须在 `ROOM_RECOVER_SNAPSHOT` 处理完成后再恢复输入。

------

## 14.3 重连失败后

```text
InputManager.disable()
MoveInputSender.stop()
SkillButtonController.disable()
```

然后跳转：

```text
SettlementScene 或 LobbyScene
```

------

# 15. 状态同步处理

## 15.1 重连前

重连期间暂停普通快照处理。

如果旧连接上还有残留消息：

```text
丢弃
```

判断依据：

1. 连接实例 ID 不一致。
2. 当前状态为 RECONNECTING。
3. 消息来自旧 WsClient。

------

## 15.2 重连后

收到 `ROOM_RECOVER_SNAPSHOT` 后，不做增量合并，直接全量重建。

原因：

1. 本地状态可能已经过期。
2. 断线期间发生了很多变化。
3. 全量恢复更安全。
4. MVP 实现更简单。

------

# 16. 结算找回设计

## 16.1 触发场景

以下情况需要查询结算：

1. 重连失败原因是 `ROOM_FINISHED`。
2. 重连失败原因是 `ROOM_NOT_FOUND`。
3. 客户端收到 `GAME_END` 后未收到 `SETTLEMENT_RESULT`。
4. WebSocket 断开时 Battle 状态已经是 ENDING。
5. 玩家回到大厅时发现有未查看结算，P1。

------

## 16.2 查询接口

优先：

```http
GET /api/settlements/{roomId}/me
```

兜底：

```http
GET /api/records/latest-settlement
```

------

## 16.3 查询结果处理

| 结果       | 客户端处理                 |
| ---------- | -------------------------- |
| 查询成功   | 进入 SettlementScene       |
| 结算处理中 | 显示结算中，可稍后重试     |
| 结算不存在 | 返回大厅，提示稍后查看战绩 |
| 接口失败   | 返回大厅，Toast 提示       |

------

# 17. H5 特殊处理

## 17.1 页面切后台

浏览器切后台后，定时器可能被降频，WebSocket 可能不稳定。

处理：

```text
visibilitychange hidden
  ↓
停止输入
  ↓
记录 hiddenTime
```

恢复时：

```text
visibilitychange visible
  ↓
检查当前 WebSocket 状态
  ↓
如果连接正常，发送 PING 校验
  ↓
如果连接异常，进入重连流程
```

------

## 17.2 页面刷新

如果玩家刷新页面，内存状态丢失。

MVP 处理：

```text
刷新后进入 BootScene
  ↓
读取本地 roomId / reconnectToken
  ↓
调用 /api/rooms/recoverable，P1
  ↓
可恢复 → 进入 GameScene 重连
  ↓
不可恢复 → LobbyScene
```

MVP 初版可以先不支持刷新恢复。

P1 再实现。

------

## 17.3 浏览器关闭

浏览器关闭时不保证能发送退出消息。

因此不能依赖：

```text
beforeunload 发送可靠请求
```

服务端应通过心跳超时判断断线。客户端只做尽力关闭。

------

# 18. 本地存储设计

## 18.1 存储内容

```json
{
  "roomId": "r_90001",
  "wsUrl": "wss://game-01.example.com/ws",
  "serverId": "gs_01",
  "reconnectToken": "reconnect_token_xxx",
  "lastSnapshotSeq": 3001,
  "lastTickSeq": 520,
  "lastEnterRoomTime": 1710000000000
}
```

------

## 18.2 写入时机

| 字段            | 写入时机               |
| --------------- | ---------------------- |
| roomId          | 匹配成功               |
| wsUrl           | 匹配成功               |
| serverId        | 匹配成功               |
| reconnectToken  | ENTER_ROOM_RESULT 成功 |
| lastSnapshotSeq | 每次处理快照后         |
| lastTickSeq     | 每次处理快照后         |

------

## 18.3 清理时机

| 场景                   | 清理                               |
| ---------------------- | ---------------------------------- |
| 收到 SETTLEMENT_RESULT | 清理 roomId、wsUrl、reconnectToken |
| 返回大厅               | 清理房间相关数据                   |
| 重连失败且不可恢复     | 清理                               |
| Token 失效             | 全部清理                           |
| 主动退出对局           | 清理                               |

------

# 19. 错误处理

## 19.1 WebSocket 连接失败

```text
尝试重连
  ↓
超过次数
  ↓
查询结算或返回大厅
```

------

## 19.2 RECONNECT_RESULT 失败

按 reason 处理：

```text
ROOM_FINISHED / ROOM_NOT_FOUND
  ↓
查询结算

TOKEN_INVALID / PLAYER_NOT_IN_ROOM
  ↓
返回大厅

SERVER_ERROR
  ↓
继续尝试，超过次数后返回大厅
```

------

## 19.3 恢复快照超时

如果收到 `RECONNECT_RESULT success` 后，超过一定时间没有收到 `ROOM_RECOVER_SNAPSHOT`：

```text
recoverSnapshotTimeoutMs = 5000
```

处理：

1. 再尝试一次重连。
2. 仍失败则返回大厅或查询结算。

# 25. 总结

客户端断线重连的核心链路是：

```text
WebSocket 断开 / 心跳超时
  ↓
停止输入
  ↓
显示重连遮罩
  ↓
重新连接 Game Server
  ↓
发送 RECONNECT
  ↓
收到 RECONNECT_RESULT
  ↓
收到 ROOM_RECOVER_SNAPSHOT
  ↓
清空旧状态
  ↓
重建对战画面
  ↓
恢复输入和心跳
```

MVP 阶段重点做好：

1. 断线检测。
2. 心跳超时。
3. 重连次数控制。
4. 重连期间禁用输入。
5. 重连遮罩。
6. RECONNECT 协议。
7. 恢复快照全量重建。
8. 重连失败返回大厅。
9. 对局结束后结算找回。

不要在初版里做复杂的跨服迁移、预测回滚、后台长时间保活。
先保证玩家短时间网络抖动时能够恢复对局，长时间断线时能够安全退出或找回结算。

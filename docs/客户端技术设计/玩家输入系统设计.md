# 2. 设计目标

玩家输入系统负责把玩家在客户端上的操作转换成服务端可以理解的输入意图。

它主要解决：

```text
玩家如何控制球体移动？
移动方向如何计算？
MOVE 消息多久发送一次？
分裂按钮如何触发？
吐球按钮如何触发？
什么时候允许输入？
什么时候禁止输入？
断线、死亡、结算时如何处理输入？
```

MVP 阶段优先支持：

1. 虚拟摇杆移动。
2. MOVE 消息发送。
3. 分裂按钮预留。
4. 吐球按钮预留。
5. 输入节流。
6. 输入状态控制。
7. 网络异常时暂停输入。
8. 对局结束时停止输入。

------

# 3. 输入系统设计原则

## 3.1 客户端只发送操作意图

客户端只告诉服务端：

```text
我要往哪个方向移动
我要分裂
我要吐球
```

客户端不发送：

```text
我的最终位置
我的速度
我的质量
我吃到了谁
我获得了多少分
我是否死亡
```

这些都由服务端权威计算。

------

## 3.2 输入与渲染分离

输入系统只负责采集和发送玩家操作。

它不负责：

1. 直接修改玩家真实位置。
2. 判断碰撞结果。
3. 判断吞噬结果。
4. 修改分数。
5. 修改质量。

渲染层只根据服务端快照更新画面。

------

## 3.3 输入受状态机控制

不是任何时候都能发送输入。

只有当客户端处于：

```text
PLAYING
```

并且：

```text
WebSocket 已连接
玩家未死亡
房间未结束
未处于重连状态
```

才允许发送 MOVE / SPLIT / EJECT。

------

## 3.4 客户端做基础节流，服务端做最终校验

客户端可以限制发送频率，减少无效请求。

但最终仍由服务端校验：

1. 是否冷却结束。
2. 质量是否足够。
3. 是否存活。
4. 是否在房间中。
5. 是否发送过快。
6. 房间是否运行中。

------

# 4. 输入系统总体架构

## 4.1 模块结构

```text
Input Module
├── InputManager
├── JoystickController
├── SkillButtonController
├── MoveInputSender
├── SkillInputSender
├── InputStateMachine
├── InputRateLimiter
└── InputConfig
```

------

## 4.2 模块职责

| 模块                  | 职责                   |
| --------------------- | ---------------------- |
| InputManager          | 输入系统总入口         |
| JoystickController    | 虚拟摇杆控制           |
| SkillButtonController | 分裂、吐球按钮控制     |
| MoveInputSender       | MOVE 消息发送          |
| SkillInputSender      | SPLIT / EJECT 消息发送 |
| InputStateMachine     | 输入状态控制           |
| InputRateLimiter      | 输入限频               |
| InputConfig           | 输入参数配置           |

------

## 4.3 输入链路

```text
玩家拖动摇杆
  ↓
JoystickController 计算方向
  ↓
InputManager 保存当前方向
  ↓
MoveInputSender 按固定频率发送 MOVE
  ↓
WsClient 发送到 Game Server
```

技能链路：

```text
玩家点击分裂 / 吐球
  ↓
SkillButtonController
  ↓
InputStateMachine 判断是否可输入
  ↓
InputRateLimiter 判断是否超频
  ↓
SkillInputSender 发送 SPLIT / EJECT
```

# 5. 输入状态机设计

## 5.1 输入状态

| 状态          | 说明                 |
| ------------- | -------------------- |
| DISABLED      | 输入不可用           |
| WAITING_START | 等待游戏开始         |
| PLAYING       | 可以输入             |
| DEAD          | 玩家死亡，不能输入   |
| RECONNECTING  | 正在重连，暂停输入   |
| ENDING        | 游戏结束中，停止输入 |
| SETTLED       | 已结算，停止输入     |

------

## 5.2 状态流转

```text
进入 GameScene
  ↓
DISABLED
  ↓ 入房成功
WAITING_START
  ↓ GAME_START
PLAYING
  ↓ 玩家死亡
DEAD
  ↓ GAME_END
ENDING
  ↓ SETTLEMENT_RESULT
SETTLED
```

断线重连：

```text
PLAYING
  ↓ WebSocket 断开
RECONNECTING
  ↓ 重连成功
PLAYING
  ↓ 重连失败
DISABLED
```

------

## 5.3 各状态下允许的输入

| 状态          | MOVE   | SPLIT  | EJECT  |
| ------------- | ------ | ------ | ------ |
| DISABLED      | 不允许 | 不允许 | 不允许 |
| WAITING_START | 不允许 | 不允许 | 不允许 |
| PLAYING       | 允许   | 允许   | 允许   |
| DEAD          | 不允许 | 不允许 | 不允许 |
| RECONNECTING  | 不允许 | 不允许 | 不允许 |
| ENDING        | 不允许 | 不允许 | 不允许 |
| SETTLED       | 不允许 | 不允许 | 不允许 |

# 6. 虚拟摇杆设计

## 6.1 页面位置

横屏布局中，虚拟摇杆放在左下角。

```text
GameScene
└── UIRoot
    └── JoystickPanel，左下角
```

推荐位置：

| 属性       | 建议          |
| ---------- | ------------- |
| 锚点       | 左下          |
| 距左边距   | 120px         |
| 距底边距   | 120px         |
| 摇杆半径   | 120px ~ 160px |
| 摇杆透明度 | 50% ~ 70%     |

------

## 6.2 摇杆组成

```text
JoystickPanel
├── JoystickBg
└── JoystickHandle
```

| 节点           | 说明       |
| -------------- | ---------- |
| JoystickBg     | 摇杆底盘   |
| JoystickHandle | 摇杆操作点 |

------

## 6.3 摇杆操作

支持：

1. 按下。
2. 拖动。
3. 松开。
4. 离开触控区域。

------

## 6.4 方向计算

玩家拖动摇杆时，计算向量：

```text
dx = touchX - centerX
dy = touchY - centerY
distance = sqrt(dx * dx + dy * dy)
```

归一化方向：

```text
direction.x = dx / max(distance, 1)
direction.y = dy / max(distance, 1)
```

如果距离小于死区：

```text
direction = { x: 0, y: 0 }
```

------

## 6.5 摇杆死区

避免手指轻微抖动导致持续移动。

推荐：

```text
deadZone = 0.08 ~ 0.15
```

如果：

```text
distance / joystickRadius < deadZone
```

则认为没有移动输入。

------

## 6.6 摇杆限制

摇杆操作点不能超过底盘范围。

如果拖动距离大于半径：

```text
handlePosition = normalizedDirection * joystickRadius
```

------

## 6.7 松手策略

玩家松开摇杆后：

```text
direction = { x: 0, y: 0 }
```

并发送一次停止 MOVE，避免服务端继续保持旧方向。

------

# 7. MOVE 输入设计

## 7.1 MOVE 消息内容

```json
{
  "type": "MOVE",
  "seq": 1001,
  "traceId": "trace_xxx",
  "clientTime": 1710000000200,
  "roomId": "r_90001",
  "data": {
    "direction": {
      "x": 0.86,
      "y": 0.51
    }
  }
}
```

------

## 7.2 MOVE 发送频率

客户端渲染可以 60 FPS，但 MOVE 不需要每帧发送。

推荐：

```text
moveSendIntervalMs = 50
```

即：

```text
每秒最多发送 20 次 MOVE
```

------

## 7.3 MOVE 发送策略

MVP 推荐：

```text
对局中每 50ms 发送一次当前方向
```

优点：

1. 实现简单。
2. 服务端输入连续。
3. 不容易出现方向丢失。

后续可优化为：

```text
方向变化时立即发送
方向未变化时低频保活发送
```

------

## 7.4 停止移动

玩家松开摇杆时，需要发送：

```json
{
  "type": "MOVE",
  "data": {
    "direction": {
      "x": 0,
      "y": 0
    }
  }
}
```

并且可以连续发送 1 ~ 2 次，降低丢包影响。

------

## 7.5 MOVE 本地保存

InputManager 维护：

```text
currentDirection
lastSentDirection
lastMoveSendTime
```

------

# 8. 分裂输入设计

## 8.1 分裂按钮位置

横屏布局中，分裂按钮放在右下角。

```text
SkillPanel
├── SplitButton
└── EjectButton
```

推荐：

| 按钮        | 位置     |
| ----------- | -------- |
| SplitButton | 右下偏上 |
| EjectButton | 右下偏下 |

------

## 8.2 SPLIT 触发方式

玩家点击分裂按钮时发送一次：

```text
SPLIT
```

------

## 8.3 SPLIT 方向来源

优先级：

1. 当前摇杆方向。
2. 最近一次有效移动方向。
3. 默认方向，朝右或朝当前摄像机前方。

推荐：

```text
如果当前摇杆方向不为 0，使用当前方向
否则使用 lastValidDirection
如果 lastValidDirection 也不存在，使用 {x:1, y:0}
```

------

## 8.4 SPLIT 消息

```json
{
  "type": "SPLIT",
  "seq": 1101,
  "traceId": "trace_xxx",
  "clientTime": 1710000000300,
  "roomId": "r_90001",
  "data": {
    "direction": {
      "x": 1,
      "y": 0
    }
  }
}
```

------

## 8.5 SPLIT 本地冷却

客户端本地冷却：

```text
splitCooldownMs = 1000
```

目的：

1. 减少无效请求。
2. 改善按钮反馈。
3. 避免玩家狂点。
4. 降低服务端压力。

注意：

```text
客户端冷却只做体验优化，服务端仍要最终校验。
```

------

## 8.6 SPLIT 失败处理

服务端返回：

```text
SKILL_FAILED
```

客户端根据原因提示：

| reason              | 文案               |
| ------------------- | ------------------ |
| MASS_NOT_ENOUGH     | 质量不足，无法分裂 |
| SPLIT_COOLDOWN      | 分裂冷却中         |
| SPLIT_LIMIT_REACHED | 分身数量已达上限   |
| PLAYER_DEAD         | 已被吞噬，无法操作 |
| ROOM_NOT_RUNNING    | 对局尚未开始       |

------

# 9. 吐球输入设计

## 9.1 EJECT 触发方式

支持两种方式：

| 方式 | 说明                     |
| ---- | ------------------------ |
| 点击 | 发送一次 EJECT           |
| 长按 | 按固定频率连续发送 EJECT |

MVP 推荐先支持点击。
P1 再支持长按连续吐球。

------

## 9.2 EJECT 方向来源

与 SPLIT 一致：

1. 当前摇杆方向。
2. 最近一次有效移动方向。
3. 默认方向。

------

## 9.3 EJECT 消息

```json
{
  "type": "EJECT",
  "seq": 1201,
  "traceId": "trace_xxx",
  "clientTime": 1710000000400,
  "roomId": "r_90001",
  "data": {
    "direction": {
      "x": 1,
      "y": 0
    }
  }
}
```

------

## 9.4 EJECT 限频

推荐：

```text
ejectIntervalMs = 150
```

即：

```text
每 150ms 最多发送一次 EJECT
```

服务端仍做最终限频。

------

## 9.5 EJECT 失败处理

常见失败原因：

| reason           | 文案               |
| ---------------- | ------------------ |
| MASS_NOT_ENOUGH  | 质量不足，无法吐球 |
| EJECT_COOLDOWN   | 操作过于频繁       |
| PLAYER_DEAD      | 已被吞噬，无法操作 |
| ROOM_NOT_RUNNING | 对局尚未开始       |

------

# 10. 技能按钮状态设计

## 10.1 按钮状态

| 状态             | 表现                 |
| ---------------- | -------------------- |
| ENABLED          | 可点击               |
| DISABLED         | 不可点击             |
| COOLDOWN         | 冷却中               |
| MASS_NOT_ENOUGH  | 质量不足，置灰       |
| DEAD             | 玩家死亡，隐藏或置灰 |
| NETWORK_DISABLED | 网络异常，置灰       |

------

## 10.2 按钮状态来源

按钮状态由以下数据共同决定：

1. InputState。
2. 玩家是否存活。
3. 当前质量。
4. 冷却时间。
5. WebSocket 状态。
6. 房间状态。

------

## 10.3 MVP 策略

MVP 可以先简化：

1. PLAYING 状态下按钮可点击。
2. 点击后进入本地冷却。
3. 服务端失败后 Toast 提示。
4. 暂不根据质量实时置灰，后续优化。

------

# 11. 输入与网络状态关系

## 11.1 WebSocket 未连接

不允许发送任何对战输入。

```text
MOVE 不发送
SPLIT 不发送
EJECT 不发送
```

UI 表现：

```text
技能按钮置灰
摇杆不可用
显示网络异常或重连中
```

------

## 11.2 正在重连

进入 RECONNECTING 状态后：

1. 停止 MOVE 定时器。
2. 禁止技能按钮。
3. 保留当前摇杆位置也不发送。
4. 重连成功后恢复输入。
5. 重连失败后清理输入状态。

------

## 11.3 对局结束

收到 GAME_END 后：

1. 停止 MOVE 定时发送。
2. 禁用摇杆。
3. 禁用技能按钮。
4. 清理当前方向。
5. 等待结算结果。

------

# 12. 输入与玩家状态关系

## 12.1 玩家死亡

如果服务端快照中当前玩家已经死亡，或者收到 PLAYER_DEAD 事件：

1. 输入状态变为 DEAD。
2. 停止 MOVE。
3. 技能按钮置灰。
4. 摇杆隐藏或不可用。
5. 等待结算或观战，后续支持。

------

## 12.2 玩家复活，后续支持

如果后续支持复活：

```text
DEAD
  ↓ RESPAWN
PLAYING
```

MVP 暂不支持复活。

# 14. 输入日志设计

| ---------------------- | ------------------ |

| input_disabled         | 输入禁用           |
| joystick_start         | 摇杆开始           |
| joystick_end           | 摇杆结束           |

------

## 14.2 日志示例

```json

  "roomId": "r_90001",

    "x": 1,
    "y": 0
  },

}
```

MOVE 属于高频日志，默认不输出，调试时按采样输出。

# 15. 异常处理

## 15.1 摇杆事件丢失

如果触控取消或浏览器焦点丢失：

1. 立即重置方向为 0。
2. 发送停止 MOVE。
3. 重置摇杆 UI。

------

## 15.2 多指触控

MVP 简化：

1. 摇杆只跟踪第一个触点。
2. 技能按钮独立响应点击。
3. 避免多个触点同时控制摇杆。

后续可以完善多指操作体验。

------

## 15.3 窗口失焦

H5 页面失焦时：

1. 停止输入。
2. 发送停止 MOVE。
3. 等待重新聚焦后恢复。
4. 如果 WebSocket 断开，进入重连流程。

------

# 16. 与其他模块关系

## 16.1 与 WebSocket 协议关系

输入系统调用 WsClient 发送：

1. MOVE。
2. SPLIT。
3. EJECT。

输入系统不直接处理服务端快照。

------

## 16.2 与状态同步关系

状态同步会更新当前玩家状态：

1. 是否存活。
2. 当前质量。
3. 房间状态。
4. 是否结束。

输入系统根据这些状态决定按钮是否可用。

------

## 16.3 与渲染系统关系

输入系统只控制 UI 交互，不直接改服务端权威位置。

但可以：

1. 更新摇杆 UI。
2. 更新技能按钮冷却表现。
3. 触发本地点击音效。
4. 后续做轻量本地预测。

------

# 19. 总结

玩家输入系统的核心链路是：

```text
玩家拖动摇杆
  ↓
计算方向
  ↓
按 50ms 发送 MOVE
  ↓
服务端 Tick 处理
  ↓
客户端接收快照
  ↓
画面表现移动结果
```

技能输入链路是：

```text
玩家点击分裂 / 吐球
  ↓
客户端检查输入状态和本地冷却
  ↓
发送 SPLIT / EJECT
  ↓
服务端校验
  ↓
成功通过快照表现
  ↓
失败返回 SKILL_FAILED
```

MVP 阶段重点做好：

1. 虚拟摇杆。
2. MOVE 固定频率发送。
3. 输入状态机。
4. 分裂 / 吐球按钮预留。
5. 本地限频。
6. 网络异常时禁用输入。
7. 对局结束时停止输入。
8. 玩家死亡时停止输入。

先保证输入链路简单、稳定、可控，后续再逐步增强长按吐球、复杂技能、预测和弱网手感优化。

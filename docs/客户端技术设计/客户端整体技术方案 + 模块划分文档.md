# 2. 客户端建设目标

## 2.1 产品目标

客户端需要支撑玩家完成一局完整游戏流程：

```text
启动游戏
  ↓
游客登录
  ↓
进入大厅
  ↓
开始匹配
  ↓
进入房间
  ↓
加载对战场景
  ↓
控制球体移动
  ↓
接收服务端状态同步
  ↓
展示局内排行榜
  ↓
游戏结束
  ↓
展示结算页
  ↓
返回大厅或再来一局
```

MVP 阶段优先保证：

1. 玩家可以进入游戏。
2. 玩家可以开始匹配。
3. 玩家可以进入对战。
4. 玩家可以通过摇杆控制移动。
5. 玩家可以看到自己、其他玩家、食物。
6. 玩家可以看到局内排行榜。
7. 玩家可以收到结算结果。
8. 玩家可以返回大厅。

------

## 2.2 技术目标

| 目标           | 说明                                       |
| -------------- | ------------------------------------------ |
| 模块边界清晰   | 页面、网络、协议、渲染、输入、状态管理分层 |
| 易于接入服务端 | HTTP 和 WebSocket 职责分离                 |
| 支持实时同步   | 能处理服务端快照、排行榜、结算等消息       |
| 支持后续扩展   | 预留分裂、吐球、AOI、重连、皮肤等能力      |
| 渲染性能可控   | 使用对象池、节点复用、分层渲染             |
| 状态来源明确   | 对战核心状态以服务端快照为准               |
| 代码组织规范   | Cocos 目录结构清晰，便于迭代               |
| MVP 可快速落地 | 初期不引入过度复杂架构                     |

# 3. 技术选型

## 3.1 客户端技术栈

| 技术                   | 用途                                   |
| ---------------------- | -------------------------------------- |
| Cocos Creator 3.x      | 2D 游戏客户端引擎                      |
| TypeScript             | 客户端主要开发语言                     |
| Cocos UI 系统          | 登录、大厅、匹配、结算等 UI            |
| Cocos Node / Component | 游戏对象和场景组织                     |
| WebSocket              | 实时对战通信                           |
| HTTP                   | 登录、匹配、战绩、排行榜等普通接口     |
| JSON                   | MVP 阶段通信协议                       |
| Protobuf               | 后续协议优化                           |
| LocalStorage           | 本地保存 token、roomId、reconnectToken |
| 对象池                 | 球体、食物、吐出物等对象复用           |

------

## 3.2 为什么选择 Cocos Creator

项目是 2D 球球类实时对战游戏，Cocos Creator 更适合：

1. 2D 场景渲染。
2. 球体、食物、地图对象展示。
3. 摄像机跟随和缩放。
4. UI 面板开发。
5. 移动端触控输入。
6. 对象池和资源管理。
7. H5 和移动端多平台发布。

相比 React / Vue + Canvas，Cocos 不需要手动封装完整游戏引擎能力。
相比 Unity，Cocos 对 2D 轻量休闲游戏更轻，更适合当前学习和 MVP。

# 6. 客户端核心模块划分

3. 初始化网络模块。
4. 加载基础资源。
5. 检查本地 token。
6. 判断进入登录页还是大厅页。

### MVP 功能

| 功能             | 是否需要 |
| ---------------- | -------- |
| 加载本地配置     | 需要     |
| 初始化全局管理器 | 需要     |

| 自动登录         | 需要     |
| 版本强更         | 暂不实现 |
| 资源热更新       | 暂不实现 |

------

## 6.2 登录模块 Auth Module

### 职责

1. 游客登录。
2. 保存 accessToken。
3. 处理 token 过期。
4. 获取用户基础信息。
5. 后续支持注册登录。

### MVP 功能

| 功能           | 说明                          |

| 游客登录       | 调用 `/api/auth/guest-login`  |

| 登录失败处理   | 展示错误提示                  |
| 正式账号登录   | 暂不实现                      |

### MVP 功能

## 6.5 网络模块 Network Module

网络模块分为 HTTP 和 WebSocket。

```text
Network Module
├── HttpClient
├── WsClient
├── RequestInterceptor
├── ResponseInterceptor
├── HeartbeatClient
├── ReconnectClient
└── NetworkErrorHandler
```

### HTTP 职责

用于非实时业务：

1. 登录。
2. 匹配。
3. 查询用户资料。
4. 查询战绩。
5. 查询排行榜。
6. 查询任务。
7. 查询结算结果。

### WebSocket 职责

用于实时对战：

1. 入房认证。
2. Ready。
3. 移动输入。
4. 分裂输入。
5. 吐球输入。
6. 接收房间快照。
7. 接收局内排行榜。
8. 接收游戏结束。
9. 接收结算结果。
10. 心跳和重连。

### 职责

1. 统一定义消息类型。

| GAME_START        | Server → Client | 游戏开始       |
| MOVE              | Client → Server | 移动输入       |
| SPLIT             | Client → Server | 分裂           |
| EJECT             | Client → Server | 吐球           |
| ROOM_SNAPSHOT     | Server → Client | 房间状态快照   |
| RANK_UPDATE       | Server → Client | 局内排行榜     |
| GAME_END          | Server → Client | 游戏结束       |
| SETTLEMENT_RESULT | Server → Client | 结算结果       |
| PING              | Client → Server | 心跳           |
| PONG              | Server → Client | 心跳响应       |

## 6.8 对战核心模块 Battle Module

### 职责

1. 管理对战生命周期。
2. 接收快照。
3. 驱动实体更新。
4. 驱动 UI 更新。

## 6.10 输入控制模块 Input Module

### 职责

1. 虚拟摇杆。
2. 移动方向计算。
3. 分裂按钮。
4. 吐球按钮。
5. 输入节流。
6. 网络发送输入。

### MVP 输入

| 输入  | 说明         |
| ----- | ------------ |
| MOVE  | 摇杆方向     |
| SPLIT | 点击分裂按钮 |
| EJECT | 点击吐球按钮 |

### 输入原则

客户端只发送操作意图：

```text

分裂方向
吐球方向
```

客户端不发送：

```text

最终质量
是否吃到玩家
是否获得分数
```

# 8. 对战场景设计概要

## 8.1 GameScene 组成

```text
GameScene
├── MapLayer
├── FoodLayer
├── EjectedMassLayer
├── PlayerLayer
├── EffectLayer
├── UILayer
│   ├── GameHUD
│   ├── RankPanel
│   ├── Joystick
│   ├── SkillButtons
│   └── ReconnectPanel
└── Camera
```

------

## 8.2 渲染层级

| 层级             | 内容                       |
| ---------------- | -------------------------- |
| MapLayer         | 地图背景、边界             |
| FoodLayer        | 食物                       |
| EjectedMassLayer | 吐出物                     |
| VirusLayer       | 刺球，后续支持             |
| PlayerLayer      | 玩家球体                   |
| EffectLayer      | 吞噬、分裂、死亡特效       |
| UILayer          | 排行榜、摇杆、按钮、倒计时 |

------

## 8.3 对战渲染原则

1. 地图对象和 UI 对象分层。
2. 食物使用对象池。
3. 玩家球体使用对象池。
4. 快照驱动实体更新。
5. 不在渲染层写业务规则。
6. 客户端只做表现，不做权威判定。
7. 大量对象避免频繁创建和销毁。

------

# 9. 状态同步设计概要

## 9.1 服务端快照驱动

客户端接收服务端快照：

```text
ROOM_SNAPSHOT
  ↓
SnapshotBuffer
  ↓
GameState
  ↓
EntityManager
  ↓
View 更新
```

------

## 9.2 MVP 快照处理

MVP 阶段可以先做简单处理：

1. 接收全量快照。
2. 更新玩家对象。
3. 更新食物对象。
4. 删除不存在对象。
5. 更新排行榜。
6. 更新倒计时。

------

## 9.3 后续优化

后续支持：

1. SnapshotBuffer。
2. 插值渲染。
3. 增量快照。
4. AOI 快照。
5. Protobuf。
6. 快照丢失检测。
7. 弱网恢复。

# 10. 客户端性能策略

## 10.1 MVP 性能策略

| 策略             | 说明                      |
| ---------------- | ------------------------- |
| 对象池           | 食物、球体、吐出物复用    |
| 分层渲染         | 地图、食物、玩家、UI 分层 |
| 减少创建销毁     | 快照更新时复用节点        |
| 限制 UI 刷新频率 | 排行榜 1 秒刷新一次       |
| 控制食物数量     | MVP 不渲染全图过多食物    |
| 按需加载资源     | 进入对战前预加载          |
| 减少复杂特效     | 初期只做基础表现          |

------

## 10.2 后续优化策略

1. AOI 视野同步。
2. 增量快照。
3. Protobuf 协议。
4. 批量更新食物。
5. 合并绘制，后续评估。
6. 降低远处对象刷新频率。

# 14. 客户端设计约束

## 14.1 客户端不做权威判定

客户端不能决定：

1. 是否吃到食物。
2. 是否吞噬玩家。
3. 是否死亡。
4. 最终分数。
5. 最终排名。
6. 奖励数量。
7. 资产变化。

这些必须由服务端决定。

------

## 14.2 客户端只做表现和输入

客户端负责：

1. 采集输入。
2. 展示场景。
3. 播放动画。
4. 显示 UI。
5. 展示错误提示。
6. 保持本地体验流畅。

------

## 14.3 网络异常必须有反馈

所有网络异常都要有 UI 提示：

1. 登录失败。
2. 匹配失败。
3. 入房失败。
4. WebSocket 断开。
5. 重连失败。
6. 结算查询失败。

------

## 14.4 所有重要操作要防重复点击

需要防重复：

1. 游客登录。
2. 开始匹配。
3. 取消匹配。
4. 领取任务奖励。
5. 再来一局。
6. 返回大厅。
7. 重连请求。

------

# 15. 总结

客户端 MVP 的核心目标不是把所有系统都做完整，而是先打通一条最小可运行链路：

```text
游客登录
  ↓
大厅
  ↓
开始匹配
  ↓
进入对战
  ↓
控制移动
  ↓
接收状态同步
  ↓
展示排行榜
  ↓
展示结算
  ↓
返回大厅
```

客户端整体模块可以按以下结构推进：

```text
场景层
  ↓
UI 层
  ↓
网络层
  ↓
协议层
  ↓
游戏状态层
  ↓
实体渲染层
  ↓
输入控制层
```

MVP 阶段优先实现：

1. BootScene。
2. LoginScene。
3. LobbyScene。
4. MatchScene。
5. GameScene。
6. SettlementScene。
7. HttpClient。
8. WsClient。
9. MessageDispatcher。
10. GameState。
11. EntityManager。
12. InputManager。
13. PlayerBallView。
14. FoodView。
15. RankPanel。
16. SettlementPanel。

暂时不要实现商城、皮肤、好友、聊天、组队、观战、回放、赛季、复杂任务和复杂特效。
先把客户端“能进入一局、能玩一局、能结束一局”做稳定，后续模块才有继续扩展的基础。

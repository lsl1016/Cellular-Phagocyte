# 2. 客户端 MVP 总目标

客户端 MVP 的目标不是一次性完成完整商业游戏，而是先完成一条最小可运行链路：

```text
启动客户端
  ↓
游客登录
  ↓
进入大厅
  ↓
开始匹配
  ↓
进入对战
  ↓
WebSocket 入房
  ↓
控制球体移动
  ↓
接收服务端快照
  ↓
展示玩家和食物
  ↓
展示局内排行榜
  ↓
接收游戏结束
  ↓
展示结算页
  ↓
返回大厅
```

------

# 3. MVP 范围

| -------------- | ------------------------------------------- |

| 基础异常处理   | 登录失败、匹配失败、入房失败、连接断开      |

# 8. 阶段 3：HTTP 接入与登录匹配

## 8.1 目标

接入服务端 HTTP 接口，完成真实登录、用户信息、匹配流程。

------

## 8.2 HTTP 基础任务

| 任务       | 说明                                    |
| ---------- | --------------------------------------- |
| HttpClient | 封装 GET / POST                         |
| 请求头处理 | Authorization、Content-Type、X-Trace-Id |
| 响应解析   | 统一处理 code / message / data          |
| 错误处理   | 超时、未登录、服务端错误                |
| Token 注入 | 登录后自动携带 token                    |
| Token 失效 | 清理本地状态并跳转 LoginScene           |

------

## 8.3 ApiService 任务

| 方法            | 接口                               |
| --------------- | ---------------------------------- |
| guestLogin      | `POST /api/auth/guest-login`       |
| getMe           | `GET /api/users/me`                |
| getMyAssets     | `GET /api/assets/me`               |
| startMatch      | `POST /api/match/start`            |
| cancelMatch     | `POST /api/match/cancel`           |
| getMatchStatus  | `GET /api/match/status`            |
| getMySettlement | `GET /api/settlements/{roomId}/me` |

------

## 8.4 业务任务

| 模块              | 任务                             |
| ----------------- | -------------------------------- |
| AuthManager       | 游客登录、token 保存、登录态校验 |
| LobbyManager      | 查询用户资料、资产               |
| MatchManager      | 开始匹配、取消匹配、轮询状态     |
| SettlementManager | 查询结算结果，后续使用           |

------

## 8.5 匹配流程

```text
LobbyScene 点击开始游戏
  ↓
POST /api/match/start
  ↓
保存 matchId
  ↓
进入 MatchScene
  ↓
每 1 秒查询 /api/match/status
  ↓
MATCHED
  ↓
保存 roomId / wsUrl / enterToken
  ↓
进入 GameScene
```

------

## 8.6 验收标准

1. 游客登录接口接入成功。
2. token 能保存到本地。
3. 刷新页面后能自动校验登录态。
4. 大厅能展示真实用户信息和资产。
5. 点击开始游戏能进入匹配。
6. 匹配成功后能拿到 roomId、wsUrl、enterToken。
7. 取消匹配能返回大厅。
8. HTTP 异常有 Toast 提示。

------

# 9. 阶段 4：WebSocket 接入与入房

## 9.1 目标

完成 GameScene 与 Game Server 的 WebSocket 连接，打通入房和 Ready 流程。

------

## 9.2 网络类任务

| 类                  | 任务                                     |
| ------------------- | ---------------------------------------- |
| WsClient            | connect、send、close、onMessage、onClose |
| MessageCodec        | JSON 编码、解码、基础校验                |
| WsMessageDispatcher | 按 type 分发消息                         |
| HeartbeatClient     | PING / PONG                              |
| NetworkState        | 保存 WS 状态                             |
| NetworkErrorHandler | 处理 WS 异常                             |

------

## 9.3 协议任务

定义：

```text
MessageType
WsEnvelope
EnterRoomData
EnterRoomResultData
ReadyData
GameStartData
RoomSnapshotData
RankUpdateData
GameEndData
SettlementResultData
ErrorData
```

------

## 9.4 入房流程

```text
进入 GameScene
  ↓
WsClient.connect(wsUrl)
  ↓
连接成功
  ↓
发送 ENTER_ROOM
  ↓
收到 ENTER_ROOM_RESULT success
  ↓
加载对战资源
  ↓
发送 READY
  ↓
等待 GAME_START
```

------

## 9.5 需要处理的消息

| 消息              | 处理            |
| ----------------- | --------------- |
| ENTER_ROOM_RESULT | 入房成功 / 失败 |
| GAME_START        | 开始对战        |
| ERROR             | 错误提示        |
| PONG              | 心跳响应        |

------

## 9.6 验收标准

1. GameScene 能连接 Game Server。
2. 能发送 ENTER_ROOM。
3. 能收到 ENTER_ROOM_RESULT。
4. 入房成功后能发送 READY。
5. 能收到 GAME_START。
6. WebSocket 断开时能提示。
7. 心跳 PING / PONG 可用。
8. GameScene 退出时能关闭 WebSocket。

------

# 11. 阶段 6：输入与状态同步

## 11.1 目标

玩家可以通过摇杆发送 MOVE，客户端可以接收 ROOM_SNAPSHOT 并更新画面。

------

## 11.2 输入系统任务

| 类                 | 任务                 |
| ------------------ | -------------------- |
| InputManager       | 输入总控             |
| JoystickController | 触摸、拖动、方向计算 |
| MoveInputSender    | 每 50ms 发送 MOVE    |
| InputStateMachine  | 控制是否允许输入     |
| InputRateLimiter   | 预留技能限频         |

------

## 11.3 MOVE 任务

| 任务          | 说明                 |
| ------------- | -------------------- |
| 方向计算      | x / y 范围 -1 到 1   |
| 死区处理      | 小于 deadZone 视为 0 |
| MOVE 限频     | 50ms 一次            |
| 松手停止      | 发送 `{x:0,y:0}`     |
| 断线停止      | 停止 MOVE            |
| GAME_END 停止 | 停止 MOVE            |

------

## 11.4 状态同步任务

| 类                  | 任务                         |
| ------------------- | ---------------------------- |
| BattleState         | 保存 players / balls / foods |
| SnapshotReceiver    | 处理 ROOM_SNAPSHOT           |
| StateReconciler     | 计算新增、更新、删除         |
| RenderSystem        | 每帧更新显示                 |
| InterpolationSystem | 目标插值                     |

------

## 11.5 快照处理流程

```text
收到 ROOM_SNAPSHOT
  ↓
校验 roomId
  ↓
校验 seq / tickSeq
  ↓
更新 BattleState
  ↓
StateReconciler 计算变化
  ↓
EntityManager 创建 / 更新 / 删除
  ↓
RenderSystem 每帧插值显示
```

------

## 11.6 验收标准

1. 摇杆可控制方向。
2. MOVE 按 50ms 发送。
3. 松手后能发送停止方向。
4. 服务端收到 MOVE 后，快照能反映移动结果。
5. 客户端能根据 ROOM_SNAPSHOT 更新自己和其他玩家位置。
6. 食物新增、消失能正确更新。
7. 旧快照会被丢弃。
8. 位置更新有基础插值，不明显跳动。
9. 游戏结束后输入停止。

------

# 12. 阶段 7：排行榜与结算闭环

## 12.1 目标

完成局内排行榜、游戏结束、结算页、返回大厅流程。

------

## 12.2 排行榜任务

| 任务             | 说明                |
| ---------------- | ------------------- |
| 监听 RANK_UPDATE | 接收服务端排行榜    |

------

## 12.3 游戏结束任务

| 消息                  | 客户端处理                   |
| --------------------- | ---------------------------- |
| GAME_END              | 停止输入、显示结算中         |
| SETTLEMENT_PROCESSING | 继续等待                     |
| SETTLEMENT_RESULT     | 保存结算、跳 SettlementScene |
| SETTLEMENT_FAILED     | 查询 HTTP 结算或提示稍后查看 |

------

## 12.4 SettlementScene 任务

| 吞噬玩家数 | eatPlayerCount |
| 吞噬食物数 | eatFoodCount   |
| 存活时间   | aliveSeconds   |
| 金币奖励   | coinReward     |
| 经验奖励   | expReward      |

------

## 12.5 返回大厅任务

```text
点击返回大厅

```

------

## 12.6 再来一局任务

```text
点击再来一局
  ↓

```

------

## 12.7 验收标准

2. RankPanel 能正确展示 Top N。
3. GAME_END 后输入停止。
4. SETTLEMENT_RESULT 后能进入结算页。
5. 结算页数据展示正确。
6. 返回大厅后资产刷新。
7. 再来一局能重新进入匹配。
8. 对局结束后 GameScene 资源和状态能清理。

# 19. 风险与应对

## 19.1 H5 渲染性能风险

| 风险             | 应对              |
| ---------------- | ----------------- |
| 食物太多导致卡顿 | 视野裁剪 + 对象池 |
| 玩家文本太多     | 控制 Label 数量   |
| 特效过多         | MVP 少做特效      |
| 节点太多         | 同屏数量限制      |
| 移动端掉帧       | 真机持续测试      |

------

## 19.2 网络同步风险

| 风险          | 应对           |
| ------------- | -------------- |
| JSON 包体过大 | 快照字段精简   |
| 快照不连续    | 全量快照兜底   |
| 弱网跳动      | 插值渲染       |
| WS 断开       | 重连或返回大厅 |
| 结算丢失      | HTTP 查询结算  |

------

## 19.3 代码结构风险

| 风险                   | 应对                                 |
| ---------------------- | ------------------------------------ |
| BattleManager 变成巨类 | 子模块拆分                           |
| View 处理业务          | 明确 View 只负责表现                 |
| UI 直接调网络          | 通过 Manager 调用                    |
| 监听不清理             | BasePanel / SceneController 统一释放 |
| 资源不释放             | GameScene dispose                    |

# 21. 总结

客户端实施建议按以下顺序推进：

```text
先搭骨架
再做页面
再接 HTTP
再接 WebSocket
再做对战渲染
再做输入同步
再做结算闭环
最后做性能和稳定性优化
```

第一阶段不要急着实现所有玩法，重点是打通：

```text
登录 → 大厅 → 匹配 → 入房 → 移动 → 同步 → 排行 → 结算
```

MVP 的客户端成功标准是：

1. 玩家能打开 H5 页面。
2. 玩家能游客登录。
3. 玩家能进入大厅。
4. 玩家能开始匹配。
5. 玩家能进入对战。
6. 玩家能通过摇杆移动。
7. 玩家能看到其他玩家和食物。
8. 玩家能看到局内排行榜。
9. 玩家能完成一局并看到结算。
10. 玩家能返回大厅或再来一局。

只要这条链路稳定，后续再扩展分裂、吐球、战绩、排行榜、任务、皮肤、商城等模块，风险会低很多。

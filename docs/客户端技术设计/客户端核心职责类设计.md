# 2. 设计目标

客户端核心类设计用于解决以下问题：

```text
每个类负责什么？
哪些类属于全局基础能力？
哪些类属于业务模块？
哪些类属于对战模块？
类之间如何依赖？
哪些逻辑不能放错地方？
后续编码时如何避免职责混乱？
```

MVP 阶段目标：

1. 明确核心类职责。
2. 明确类之间依赖方向。
3. 明确每个类的核心方法。
4. 避免 UI、网络、协议、状态、渲染混在一起。
5. 支持后续扩展排行榜、任务、战绩、皮肤、商城等模块。

# 4. 核心依赖方向

## 4.1 推荐依赖链路

```text
SceneController
  ↓
Manager
  ↓
Network / Battle / UI
  ↓
Common / Protocol
```

对战链路：

```text
WsClient
  ↓
WsMessageDispatcher
  ↓
BattleManager
  ↓
SnapshotReceiver
  ↓
BattleState
  ↓
EntityManager
  ↓
EntityView
```

输入链路：

```text
JoystickController
  ↓
InputManager
  ↓
MoveInputSender
  ↓
WsClient
```

UI 链路：

```text
SceneController
  ↓
UIManager
  ↓
Panel
  ↓
Manager
```

---

## 4.2 禁止依赖

不建议出现以下依赖：

```text
EntityView 直接调用 HttpClient
PlayerBallView 直接解析 WebSocket 消息
UI Panel 直接 new WsClient
Protocol 依赖 UI
Common 依赖业务模块
Network 直接控制具体页面
FoodView 修改 BattleState
```

正确方式：

```text
网络消息 → Dispatcher → Manager → State → View 更新
```

而不是：

```text
网络消息 → View 直接处理
```

```text
assets/scripts/app/App.ts
```

4. UI 细节。
5. WebSocket 消息处理。

# 6. AppContext

## 6.1 类定位

`AppContext` 是全局服务容器，用于统一管理全局单例。

路径：

```text
assets/scripts/app/AppContext.ts
```

---

## 6.2 职责

保存全局服务引用：

```text
logger
eventBus
storage
httpClient
apiService
wsClient
messageDispatcher
sceneRouter
uiManager
networkState
appState
```

---

## 6.3 设计原因

如果没有 `AppContext`，各模块可能到处创建实例，导致：

1. 状态不一致。
2. 单例失控。
3. 依赖混乱。
4. 测试困难。
5. 后续重构困难。

---

## 6.4 核心方法

```ts
export class AppContext {
  logger: Logger;
  eventBus: EventBus;
  storage: StorageManager;
  httpClient: HttpClient;
  apiService: ApiService;
  wsClient: WsClient;
  messageDispatcher: WsMessageDispatcher;
  sceneRouter: SceneRouter;
  uiManager: UIManager;
  networkState: NetworkState;
  appState: AppState;

  init(): void;

  reset(): void;
}
```

# 45. 类之间的主流程关系

## 45.1 启动流程

```text
BootSceneController
  ↓
AppBootstrap
  ↓
AuthManager.checkLoginState
  ↓
SceneRouter.goToLobby / goToLogin
```

---

## 45.2 登录流程

```text
LoginPanel
  ↓
AuthManager.guestLogin
  ↓
ApiService.guestLogin
  ↓
HttpClient.post
  ↓
StorageManager 保存 token
  ↓
SceneRouter.goToLobby
```

---

## 45.3 匹配流程

```text
LobbyPanel 点击开始游戏
  ↓
LobbyManager.startGame
  ↓
MatchManager.startMatch
  ↓
ApiService.startMatch
  ↓
MatchScene
  ↓
MatchManager.startPollStatus
  ↓
匹配成功
  ↓
SceneRouter.goToGame
```

---

## 45.4 入房流程

```text
GameSceneController
  ↓
BattleManager.init
  ↓
WsClient.connect
  ↓
BattleManager.sendEnterRoom
  ↓
ENTER_ROOM_RESULT
  ↓
BattleManager.sendReady
  ↓
GAME_START
  ↓
InputManager.enable
  ↓
RenderSystem.start
```

---

## 45.5 对战同步流程

```text
WsClient 收到 ROOM_SNAPSHOT
  ↓
MessageCodec.decode
  ↓
WsMessageDispatcher.dispatch
  ↓
SnapshotReceiver.handleRoomSnapshot
  ↓
BattleState.applySnapshot
  ↓
EntityManager.sync
  ↓
RenderSystem.update
  ↓
PlayerBallView / FoodView 更新
```

---

## 45.6 输入流程

```text
JoystickController
  ↓
InputManager.setDirection
  ↓
MoveInputSender 每 50ms 读取方向
  ↓
WsClient.send MOVE
```

---

## 45.7 结算流程

```text
WsClient 收到 SETTLEMENT_RESULT
  ↓
WsMessageDispatcher
  ↓
SettlementManager.handleSettlementResult
  ↓
AppState.currentSettlement
  ↓
SceneRouter.goToSettlement
  ↓
SettlementPanel.refreshSettlement
```

---

## 45.8 重连流程

```text
WsClient onClose / Heartbeat timeout
  ↓
BattleManager.handleDisconnected
  ↓
InputManager.disable
  ↓
ReconnectPanel.show
  ↓
ReconnectClient.startReconnect
  ↓
WsClient.connect
  ↓
send RECONNECT
  ↓
ROOM_RECOVER_SNAPSHOT
  ↓
BattleManager.recoverFromSnapshot
  ↓
BattleState.clear + applyRecoverSnapshot
  ↓
EntityManager.clearAll + rebuild
  ↓
InputManager.enable
```

# 48. 总结

客户端核心类可以分成六组：

```text
全局基础类
网络与协议类
业务模块类
对战核心类
UI 类
实体表现类
```

最核心的主链路是：

```text
App / AppContext
  ↓
SceneRouter
  ↓
AuthManager / MatchManager / BattleManager / SettlementManager
  ↓
HttpClient / WsClient
  ↓
SnapshotReceiver / BattleState
  ↓
EntityManager / RenderSystem
  ↓
PlayerBallView / FoodView / GameHUD
```

MVP 阶段最重要的是让这些类职责保持清晰：

1. `HttpClient` 只管 HTTP。
2. `WsClient` 只管 WebSocket 连接和收发。
3. `WsMessageDispatcher` 只管消息分发。
4. `BattleManager` 只管对战流程。
5. `BattleState` 只管状态。
6. `SnapshotReceiver` 只管快照处理。
7. `EntityManager` 只管实体 View 管理。
8. `PlayerBallView` 和 `FoodView` 只管表现。
9. `InputManager` 只管输入。
10. `SceneRouter` 只管场景跳转。
11. `UIManager` 只管 UI 管理。

只要这些核心职责不混乱，后续继续扩展战绩、排行榜、任务、皮肤、商城、好友系统时，客户端工程就能保持稳定。

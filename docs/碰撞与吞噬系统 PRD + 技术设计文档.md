# 第一部分：碰撞与吞噬系统 PRD

## 2. 模块背景

《吞噬细胞》的核心玩法是“移动、吞噬、成长、对抗”。玩家控制球体在地图中移动，通过吞噬食物和其他玩家增加质量，质量越大，体积越大，但移动速度会降低。玩家还可以通过分裂、吐球等操作进行追击、逃脱和战术配合。

碰撞与吞噬系统是游戏核心玩法模块之一，负责在服务端判断：

1. 玩家是否吃到食物。
2. 玩家是否吃到吐出物。
3. 玩家是否可以吞噬其他玩家。
4. 玩家是否触碰刺球。
5. 分裂后的多个球体如何参与碰撞。
6. 吞噬成功后质量如何变化。
7. 被吞噬对象如何从房间状态中移除。
8. 如何生成事件并同步给客户端。
9. 如何影响局内排行榜和结算数据。

本系统必须由服务端权威计算，客户端只负责表现。

------

## 3. 模块目标

### 3.1 产品目标

| 目标           | 说明                                     |
| -------------- | ---------------------------------------- |
| 玩法反馈明确   | 玩家吃到食物或吞噬敌人时，需要有明确反馈 |
| 规则简单可理解 | 大球吃小球，小球躲大球，规则直观         |
| 成长体验明显   | 吞噬后体积、得分、排名变化明显           |
| 对抗体验公平   | 吞噬判定由服务端统一计算                 |
| 支持分裂战术   | 分裂后的球体也能参与移动和吞噬           |
| 支持多人混战   | 单局多人时仍能稳定计算碰撞               |
| 支持结算统计   | 吞噬玩家数、吞噬食物数、最大质量等可统计 |

### 3.2 技术目标

| 目标            | 说明                                 |
| --------------- | ------------------------------------ |
| 服务端权威判定  | 客户端不能直接声明自己吃到了对象     |
| Tick 内统一计算 | 碰撞与吞噬在服务端 Tick 中执行       |
| 规则可配置      | 食物质量、吞噬倍率、半径计算等可配置 |
| 支持空间优化    | 后续通过网格减少碰撞检测次数         |
| 支持事件输出    | 吞噬、死亡、分裂等需要生成事件       |
| 支持排行榜更新  | 吞噬后能影响分数和排名               |
| 支持结算统计    | 对局结束时可产出玩家表现数据         |

## 4. 模块定位

碰撞与吞噬系统位于 Game Server 的 Tick 流程中。

```text
玩家输入
  ↓
移动系统更新位置
  ↓
碰撞与吞噬系统
  ↓
更新质量 / 删除对象 / 生成事件
  ↓
排行榜系统
  ↓
状态同步系统
```

本系统不直接负责客户端渲染，也不直接负责最终奖励结算，但会为它们提供事件和统计数据。

## 5. 核心设计原则

## 5.1 服务端统一裁决

所有碰撞和吞噬结果必须由服务端决定。

客户端可以发送：

```text
移动方向
分裂请求
吐球请求
```

客户端不能发送：

```text
我吃到了某个食物
我吞噬了某个玩家
我的质量变成了多少
我本局排名第几
```

------

## 5.2 先规则正确，再性能优化

MVP 阶段优先保证规则清晰、链路完整。

```text
MVP：简单距离检测 + 基础吞噬规则
优化阶段：空间网格 + AOI 共享索引
性能阶段：对象分区、批处理、热点优化
```

------

## 5.3 碰撞检测和吞噬判定分离

碰撞只表示两个对象接触或进入判定范围。
吞噬还需要满足质量、半径、保护状态、冷却状态等规则。

```text
发生碰撞 ≠ 一定吞噬成功
```

例如两个玩家球体接触，但如果质量差距不够，则不能吞噬。

------

## 5.4 吞噬结果必须可追踪

每次吞噬都应生成事件和统计记录，便于：

1. 客户端播放特效。
2. 局内排行榜更新。
3. 结算统计。
4. 反作弊排查。
5. 日志分析。

------

## 8. 核心玩法规则

## 8.1 食物吞噬规则

玩家球体与食物满足吞噬距离条件时，食物被吞噬。

规则：

1. 玩家球体与食物发生接触。
2. 食物未被其他球体吞噬。
3. 玩家处于 PLAYING 状态。
4. 房间处于 RUNNING 状态。
5. 吞噬成功后食物从房间中移除。
6. 玩家球体质量增加。
7. 玩家得分增加。
8. 生成 FOOD_EATEN 事件。

------

## 8.2 吐出物吞噬规则

玩家球体可以吞噬吐出物。

规则：

1. 玩家球体与吐出物发生接触。
2. 吐出物未处于刚生成保护期，后续支持。
3. 玩家处于 PLAYING 状态。
4. 吞噬成功后吐出物从房间中移除。
5. 玩家质量增加。
6. 生成 EJECTED_MASS_EATEN 事件。

------

## 8.3 玩家吞噬规则

大球可以吞噬小球。

基础规则：

1. 两个球体属于不同玩家。
2. 攻击方质量大于被吞噬方质量。
3. 攻击方质量达到吞噬倍率要求。
4. 双方距离满足吞噬距离条件。
5. 被吞噬方不处于出生保护状态。
6. 攻击方不处于限制状态。
7. 房间处于 RUNNING 状态。

建议公式：

```text
attacker.mass >= target.mass * eatMassRatio
```

推荐初始值：

```text
eatMassRatio = 1.2
```

------

## 8.4 同玩家分身碰撞规则

同一个玩家的多个分身之间不应立即互相吞噬。

规则：

1. 分裂后存在合体冷却时间。
2. 冷却期间，同玩家球体之间可以发生位置重叠或轻微排斥，具体策略后续设计。
3. 冷却结束后，同玩家球体可以合体。
4. 合体不算吞噬玩家。
5. 合体不增加额外得分，只合并质量。

MVP 阶段可以先简化：

```text
同一玩家的球体之间不做吞噬检测
```

合体逻辑后续单独设计。

------

## 8.5 出生保护规则

玩家刚出生或复活后可以有短暂保护。

规则：

1. 保护期间不能被其他玩家吞噬。
2. 保护期间可以吞噬食物。
3. 保护期间是否能吞噬其他玩家可配置。
4. 保护时间建议为 3 ~ 5 秒。

MVP 阶段可先不支持出生保护，后续补充。

------

## 9. 质量与半径规则

## 9.1 质量定义

质量是玩家成长的核心数值。

质量影响：

1. 球体半径。
2. 移动速度。
3. 吞噬能力。
4. 玩家得分。
5. 排行榜排名。

------

## 9.2 半径计算

推荐基础公式：

```text
radius = sqrt(mass) * radiusFactor
```

示例配置：

```text
radiusFactor = 2.5
```

------

## 9.3 速度计算

推荐基础公式：

```text
speed = baseSpeed / sqrt(massFactor)
```

也可以使用更平滑的配置曲线。
MVP 阶段只需要保证：

```text
质量越大，速度越慢
```

------

## 9.4 吞噬质量收益

食物吞噬：

```text
ball.mass += food.mass
```

吐出物吞噬：

```text
ball.mass += ejectedMass.mass
```

玩家吞噬：

```text
attacker.mass += target.mass * playerEatMassGainRatio
```

推荐初始值：

```text
playerEatMassGainRatio = 0.8
```

这样可以避免质量无限快速膨胀。

------

## 10. 吞噬距离规则

## 10.1 基础圆形碰撞

两个圆发生接触：

```text
distance(centerA, centerB) <= radiusA + radiusB
```

------

## 10.2 食物吞噬距离

建议：

```text
distance(playerBall, food) <= playerBall.radius
```

也可以使用：

```text
distance(playerBall, food) <= playerBall.radius + food.radius
```

MVP 推荐后者，简单直观。

------

## 10.3 玩家吞噬距离

玩家吞噬不能只要接触就成功，否则体验会过于敏感。

建议规则：

```text
distance(attacker, target) <= attacker.radius - target.radius * eatDepthFactor
```

或者简化为：

```text
targetCenter 进入 attacker 半径一定比例范围内
```

推荐初始配置：

```text
eatDepthFactor = 0.4
```

含义：小球需要进入大球内部一定程度，才算被吞噬。

MVP 简化规则：

```text
distance(attacker, target) <= attacker.radius
```

## 13. Tick 中的执行位置

推荐在 Tick 中的执行顺序：

```text
1. 读取输入
2. 更新玩家方向
3. 计算移动
4. 更新对象位置
5. 更新空间索引
6. 检测玩家与食物碰撞
7. 检测玩家与吐出物碰撞
8. 检测玩家与玩家碰撞
9. 处理吞噬结果
10. 更新质量、半径、速度
11. 移除被吞噬对象
12. 生成事件
13. 更新排行榜
14. 生成快照
```

原因：

1. 必须先移动，再检测碰撞。
2. 必须先更新空间索引，再查询附近对象。
3. 必须先处理吞噬，再生成快照。
4. 排行榜应基于吞噬后的最新状态。

## 15. 碰撞检测流程

## 15.1 MVP 简单检测

MVP 阶段可先使用简单遍历。

玩家吃食物：

```text
遍历玩家球体
  ↓
遍历食物
  ↓
判断距离
  ↓
满足条件则吞噬
```

玩家吃玩家：

```text
遍历玩家球体 A
  ↓
遍历玩家球体 B
  ↓
排除同一玩家
  ↓
判断质量
  ↓
判断距离
  ↓
满足条件则吞噬
```

适用：

1. 小规模房间。
2. MVP 验证。
3. 食物数量较少。
4. 快速跑通玩法闭环。

------

## 15.2 空间网格检测

优化阶段使用 SpatialGrid。

流程：

```text
1. 地图划分网格
2. 对象根据坐标加入网格
3. 玩家球体只查询周围网格对象
4. 对候选对象做精确距离判断
5. 处理吞噬结果
```

优点：

1. 减少全量遍历。
2. 适合大量食物。
3. 可与 AOI 共享空间索引。
4. 支撑单局 100 人。

------

## 15.3 网格候选查询

对某个玩家球体：

```text
1. 根据球体坐标找到所在网格
2. 根据球体半径和最大目标半径确定查询范围
3. 查询周围网格中的食物、玩家球体、吐出物
4. 生成候选对象列表
5. 逐个精确检测
```

## 16. 食物吞噬技术设计

## 16.1 检测流程

```text
1. 获取玩家球体

3. 计算距离
```

## 17. 玩家吞噬技术设计

## 17.1 检测流程

```text
1. 获取攻击方玩家球体
2. 查询附近其他玩家球体
3. 排除同一玩家球体
4. 判断攻击方质量是否满足要求
5. 判断距离是否满足吞噬要求
6. 判断目标是否处于保护状态
7. 如果满足，生成 EatResult
8. 移除目标球体
9. 攻击方增加质量
10. 判断目标玩家是否还有其他球体
11. 如果没有，目标玩家死亡
12. 更新攻击方统计
13. 写入 EventBuffer
```

# 20. 多对象冲突处理

## 20.1 一个食物被多个球体同时碰到

处理原则：

```text
同一个 Tick 内，先处理到的球体获得该食物
```

需要保证：

1. 食物只能被吞噬一次。
2. 食物吞噬后状态标记为 REMOVED。
3. 后续检测遇到 REMOVED 食物直接跳过。

------

## 20.2 两个玩家同时互相吞噬

可能出现边界情况：

```text
A 可以吃 B
B 也可能在同 Tick 被其他球吃
```

处理建议：

1. 按质量从大到小处理玩家球体。
2. 被吞噬对象立即标记为 REMOVED。
3. 已移除对象不再参与本 Tick 后续吞噬。
4. 同质量或差距不足时不发生吞噬。

------

## 20.3 同 Tick 多个吞噬结果

处理顺序建议：

```text
1. 食物吞噬
2. 吐出物吞噬
3. 玩家吞噬
4. 刺球碰撞
```

或者：

```text
玩家吞噬优先级高于食物
```

两种都可以，关键是规则必须固定且可配置。

MVP 建议：

```text
食物 → 吐出物 → 玩家
```

这样更容易实现和调试。

# 22. 状态同步关系

碰撞与吞噬系统不直接给客户端发消息，而是写入事件缓冲区，由状态同步系统下发。

```text
碰撞与吞噬系统
  ↓
EventBuffer
  ↓
SnapshotSystem
  ↓
WebSocket
  ↓
客户端播放表现
```

客户端收到事件后：

| 事件               | 客户端表现                   |
| ------------------ | ---------------------------- |
| FOOD_EATEN         | 食物消失，玩家变大           |
| PLAYER_EATEN       | 被吞噬球体消失，播放吞噬特效 |
| PLAYER_DEAD        | 展示死亡状态或结算等待       |
| EJECTED_MASS_EATEN | 吐出物消失                   |
| VIRUS_TRIGGERED    | 播放刺球触发和分裂特效       |

# 26. 性能设计

## 26.1 性能压力来源

单局 100 人时，压力主要来自：

1. 玩家球体数量增加。
2. 分裂后球体数量增加。
3. 食物对象数量较多。
4. 玩家与食物碰撞检测频繁。
5. 玩家与玩家碰撞检测复杂。
6. Tick 时间有限，不能超时太多。

------

## 26.2 MVP 性能策略

MVP 阶段：

1. 控制房间人数。
2. 控制食物数量。
3. 控制最大分身数量。
4. 先使用简单检测。
5. Tick 频率设为 20/s。
6. 通过日志观察耗时。

------

## 26.3 优化阶段策略

优化阶段：

1. 使用 SpatialGrid。
2. 只检测附近网格对象。
3. 与 AOI 共享空间索引。
4. 玩家球体按质量排序。
5. 食物检测批处理。
6. 对象移除使用标记删除。
7. 减少 Tick 内内存分配。
8. 统计每 Tick 碰撞耗时。

------

# 27. 安全与反作弊

## 27.1 作弊风险

| 作弊方式            | 防护方式                 |
| ------------------- | ------------------------ |
| 客户端伪造吃到食物  | 服务端检测食物碰撞       |
| 客户端伪造吞噬玩家  | 服务端检测玩家碰撞       |
| 客户端伪造质量      | 质量只由服务端计算       |
| 客户端伪造位置      | 位置只由服务端计算       |
| 客户端刷分裂 / 吐球 | 服务端校验冷却与质量     |
| 客户端重复提交事件  | 客户端不允许提交吞噬事件 |

------

## 27.2 服务端校验

每次吞噬前校验：

1. 房间是否 RUNNING。
2. 玩家是否 PLAYING。
3. 对象是否存在。
4. 对象是否 ACTIVE。
5. 距离是否满足。
6. 质量是否满足。
7. 目标是否未被移除。
8. 是否符合冷却和保护规则。

# 31. 总结

碰撞与吞噬系统是《吞噬细胞》的核心玩法模块。它决定了玩家如何成长、如何击败其他玩家、如何获得分数和排名。

核心链路如下：

```text
Tick 更新位置
  ↓
检测碰撞
  ↓
判断吞噬条件
  ↓
更新质量
  ↓
移除目标对象
  ↓
生成事件
  ↓
更新排行榜
  ↓
同步给客户端
```

当前阶段应优先保证：

1. 服务端权威判定。
2. 食物吞噬链路完整。
3. 玩家吞噬规则清晰。
4. 质量、半径、速度能正确更新。
5. 吞噬事件能被客户端表现。
6. 结算统计数据能被记录。
7. 后续能平滑接入 SpatialGrid、分裂、吐球、刺球等扩展玩法。
